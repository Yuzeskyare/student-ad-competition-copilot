# 广告文案：语言说服作业系统

默认完成边界：交付作品。当前赛事规则、实际提交规格与外部研究引用在完成前核对；素材/字体使用依据、AIGC后台记录及平台申报仅完成后提醒，报名身份、上传和回执不阻断作品完成。
本 Playbook 用于大广赛文案类与学院奖命题明确允许的广告文案。先读取[公共内核](../../workflow/common-competition-kernel.md)，再读取当前赛事配置、[广告文案交付规范](../../deliverables/ad-copy.md)和对应命题约束。

它规定文案如何从事实、品牌和人群任务形成可以被理解、记住和说出的语言。字符计数、文件格式和赛事白名单不在本文件重复。

## 1. 文案成立条件

广告文案必须依次成立：

`事实真实 → 命题响应 → 人群有感 → 品牌有角色 → 文体合适 → 语义完整 → 结构有效 → 声音自然 → 技术合规`

字数正确、句式整齐、押韵或出现品牌名都不能单独证明文案成立。先决定为什么说、对谁说、品牌凭什么说，再决定如何压缩和修辞。

## 2. 运行阶段与高成本边界

以下为正式作品运行。普通洞察讨论和短样段探索按[探索与正式运行衔接](../../workflow/delivery-and-recovery.md#探索与正式运行衔接)保存必要上下文，不以整套运行记录作为开始交流的条件；请求完整作品时直接进入所需正式范围。

| 阶段 | 主要产出 | 未通过时不得进入 |
| --- | --- | --- |
| 0. 命题与主张底座 | 命题约束、类别/文体、可用事实与禁用主张 | 方向生产 |
| 1. 人群任务与语言领地 | 场景、矛盾、品牌角色、竞品表达风险 | 文案定调 |
| 2. 策略方向 | 少量机制不同方向（默认最多3个展示）与选择理由 | 多稿生产 |
| 3. 多稿生产 | 1–5份通过内部筛选的候选 | 定稿 |
| 4. 人工内容门 | 语义、品牌、文体与声音评审 | 技术校验 |
| 5. 技术与状态 | 字符、纯文本、字面约束和运行清单 | 完成声明 |

短文案不因篇幅短而省略语义和品牌判断；长文案不因篇幅长而默认拥有洞察和叙事。

## 3. 阶段0：命题、类别与主张底座

### 输入

- 当前赛事、届次或赛季与具体命题；
- 官方允许的原始类别和文案形态；
- 品牌、产品、受众、主题、必用词、禁用词和长度信息；
- 产品事实、命题方主张和必要限定；
- AIGC、署名、提交和特殊合规要求。

### 必须产出

1. 命题证据；
2. 符合现有 schema 的命题约束 JSON；
3. 官方类别与内部工作子类型判定；
4. 可用事实、条件性主张、禁用主张和待确认项；
5. 硬阻塞和开放选择。

### 子类型裁定

- 官方明确给出具体文体时按官方文体；
- 官方只允许宽泛“广告文案”时，可按实际工作形态分类，用于启用相应质量检查，不宣称赛事新增限制；
- 未规定长度时使用开放边界继续，不虚构数字；
- 类别未获授权或官方规则冲突时停止对应裁定。

### 主张边界

- 命题方宣传语不自动等于已证实产品事实；
- 功效、安全、健康、价格、销量、时效和绝对化表达必须有相应证据；
- 修辞性夸张不能掩盖会被普通受众理解为事实的承诺；
- 敏感品类同时检查语境、责任归属、隐私、羞辱和误导风险。

写产品象征时，从有依据的属性或作品中可见的使用动作出发，连接感官变化、人物选择与情绪含义。例如打开、握持、分享等动作可以改变场景关系，但不能因此推断产品具有心理或生理疗效。检查普通受众会理解成什么结果、该结果是否被产品直接承诺；有误导时改写因果与表达，而非把情绪词做成黑名单或把产品退化为结尾署名。第一人称可以是叙事选择；只有涉及真实证言、个人隐私或虚构冒充事实时才澄清。

## 4. 阶段1：人群任务与语言领地

文案研究只做会改变表达选择的工作：

- 谁在什么场景遇到什么任务；
- 他们正在说什么、回避什么、误解什么；
- 品牌在这一时刻能扮演什么角色；
- 竞品和品类反复使用哪些句法、承诺、情绪和陈词；
- 哪些熟语、谐音、押韵或网络表达已过度使用或可能引发误读。

公开语料只按公共内核允许的证据边界使用。不能把热门表达直接复制成“年轻人的语言”，也不能从案例奖级推断句式有效。

### 语言任务句

进入方向生产前，用后台工作句明确：

> 让___人群在___场景，从___旧判断转向___新判断，并相信品牌因为___有资格这样说。

该句用于检查，不进入最终文案。若无法明确旧判断、新判断和品牌资格，继续研究或收窄任务。

## 5. 阶段2：形成少量机制不同的策略方向

方向差异来自语言机制和说服路径，不是同义换词。可区分的机制包括但不限于：

- 具体生活动作揭示矛盾；
- 对话或关系视角改变责任归属；
- 产品属性转译为可感知场景；
- 反常识、转折或重新定义；
- 时间、空间或行为序列压缩；
- 证言、说明、邀请、宣言或故事结构。

进入方向时继承用户已明确的表达偏好，分清创意机制、表达形式、语气与平台要求；这些维度可以组合，示例不构成固定菜单。用户明确要诗歌、散文或某种语气时直接采用；只给案例时先分析吸引力来自何处，不从图片分行或“获奖”称谓推定诗歌更优。没有明确偏好时按传播任务给推荐，必要时用短样段展示差异；只有会明显改变作品且现有信息无法支持选择时才提问，不新增文体确认关。

每个方向至少说明：

- 人群、场景与矛盾；
- 一句话传播判断；
- 品牌和产品角色；
- 拟用文体；
- 语言机制与记忆钩子；
- 事实、合规、陈词、歧义和品牌可替换风险；
- 验证办法；
- 所用方法卡及其本次输出。

方向门保留实际比较的采用/拒绝理由；不为凑数编造未考虑过的方向。入选依据是命题响应、品牌不可替换、可理解、可说和风险可控，不是单纯“更有文采”。

## 6. 阶段3：多稿生产

已有获批稳定稿的`challenge`模式先按[稳定基线合同](../../workflow/version-bound-review.md)保留原稿；初创也不要求凑足3份，最多5份是展示上限。没有成立的挑战稿时可以只保留稳定稿。

基于入选方向产生1–5份通过内部筛选的候选。有效差异可以来自：

- 叙述者或关系视角；
- 信息出现顺序；
- 句长与节奏；
- 动作、对话、清单、故事或宣言结构；
- 品牌出现时机；
- 情绪推进与收束方式。

只替换形容词、近义词、标点或尾韵不算结构不同。

### 逐稿语义骨架

每份候选在后台记录：

- 字面说了什么；
- 普通受众可能理解成什么；
- 哪个具体词或句承担产品事实；
- 哪个具体词或句承担人群矛盾；
- 哪个具体词或句承担品牌角色；
- 删除品牌名后是否仍完整成立；
- 最大误读和事实风险。

文案需要靠外部长解释才能成立时，不进入修辞打磨，先重写语义骨架。

## 7. 通用人工内容门

所有文体都检查：

1. **命题响应**：是否回答具体传播任务，而非只复述主题词；
2. **事实与暗示**：字面及常见理解是否超出证据；
3. **人性张力**：是否有具体动作、选择、关系或矛盾；
4. **品牌角色**：品牌是否有资格、有动作，而非只在结尾署名；
5. **不可替换性**：换成竞品或通用品类是否仍完全成立；
6. **清晰度**：第一次阅读能否抓住主判断；
7. **信息经济**：每个词是否推进语义，是否有空洞形容、重复和解释性尾巴；
8. **自然语言**：是否像真实中文，而非为对仗、押韵或高级感扭曲语序；
9. **记忆结构**：记忆点是否来自判断、动作或声音，而非生硬谐音；
10. **品牌声音**：语气是否符合品牌、品类和关系边界；
11. **原创风险**：是否过度接近熟语、案例原句、热梗或既有广告语；
12. **行动或落点**：文体需要行动时，下一步是否明确且合理。

用户反馈优先于内部排序。反馈按“观察 → 影响 → 修改 → 朗读/复核”记录，原候选和原决定保留。

## 8. 文体专属质量门

### 8.1 Slogan与短文案

先过语义和品牌门，再做声音层：

- 标出语法槽位：主体、动作、对象、时间、地点和结果；
- 标出各分句音节数；
- 标出自然停顿、重音和语调方向；
- 比较字面平衡与实际口播平衡；
- 朗读无韵、自然押韵和去除强押版本；
- 检查同字收尾是否只是重复，没有语义推进；
- 判断不对称是有意强调还是无意词长失衡；
- 检查品牌名加入后是否破坏节奏或像附加署名。

押韵是可选增强。若押韵破坏真实动作、自然语序、信息准确或品牌任务，删除韵脚。声音检查结果写入现有 prosody review 记录。

### 8.2 长文案与品牌故事

- 开头是否提出具体张力，而非宏大空话；
- 每一段是否推进人物、事实或判断；
- 情绪变化是否有可见原因；
- 产品是否进入事件和选择，而非结尾硬转；
- 品牌落点是否回收前文；
- 是否存在可以删除而不损失信息的段落；
- 长度是否来自任务需要，而非为了接近上限。

当用户选择诗性表达，或稿件实际依赖分节、分行、复沓与意象推进时，在同一次内容审读中检查这些形式是否产生意义：分节如何推进或对照，分行是否形成有作用的停顿/转折，意象之间能否联系，语体转换是否有意且可理解，产品动作和主题落点是否参与前文发展。指出具体句段及其阅读后果后再修订，不把断句当诗性。

多意象、跳跃、不押韵与不对称可以成立；不规定每节只能一个动作、不计数限制隐喻、不强制整齐。散文、对话或平台表达按其实际组织方式审读，不能因本节新增指导而诗歌化。只有观察到混乱、空转或品牌脱节时返修，不新增诗歌审核表、评分器或独立人工关。

### 8.3 视频、广播与表演脚本

- 时长能否由实际朗读和动作完成；
- 台词、旁白、画面、音效和动作是否各有职责；
- 场景切换、人物关系和因果是否可拍、可演、可听；
- 产品与品牌出现时机是否自然；
- 无画面或无声音时，必要信息是否仍按媒介要求成立；
- 不把策划说明写成角色台词。

### 8.4 社媒与种草文案

- 平台语态是否自然，不机械堆网络词；
- 是否提供真实细节、使用过程或可核对信息；
- 商业关系和AIGC披露是否符合命题及平台要求；
- 标题、正文、标签和行动入口是否一致；
- 是否同时说明吸引力与必要摩擦，而非伪装成无条件个人体验；
- 评论互动或二次传播是否有合理承接。

具体平台表达需要当前平台研究支持，不能把某次平台观察永久化为通用语法。

## 9. 声音评审的执行法

声音层不能只写“朗读顺畅”。至少完成：

1. 正常速度朗读；
2. 只看文本的陌生人朗读或等价盲读；
3. 标记第一次自然停顿位置；
4. 标记被意外重读、吞音或歧义的词；
5. 对并列句比较语法槽位和节拍；
6. 对尾韵判断自然韵、弱韵、无韵或强押；
7. 记录修改前后差异。

若条件不足以做外部盲读，至少由创作者间隔后朗读并明确记录限制，不得把自读当成受众验证。

## 10. 技术检查边界

内容门通过后，按交付规范和赛事配置检查：

- 文件编码、纯文本和不可见字符；
- 计数单位与长度边界；
- 类别/子类型白名单；
- 必用词、命中组和禁用词；
- emoji、Markdown、HTML、图片或作者身份字段；
- 交付后的AIGC记录/平台申报提醒、文件哈希和运行路径。

机器不能判断同义表达、语境暗示、原创性、法律合规、品牌声音、情绪质量、对仗、真实朗读和强押风险。技术通过不产生内容通过。

## 11. 硬停止与回退表

| 发现 | 回退位置 | 处理 |
| --- | --- | --- |
| 类别未授权或官方规则冲突 | 阶段0 | 解决规则，不继续定稿 |
| 核心产品主张无证据 | 阶段0 | 删除、限定或补官方证据 |
| 未规定长度被误作阻塞 | 阶段0 | 设为开放边界并继续 |
| 没有具体语言任务 | 阶段1 | 补人群、场景、旧判断、新判断和品牌资格 |
| 方向只是换词 | 阶段2 | 重做不同说服机制 |
| 文案需靠解释才能成立 | 阶段3 | 重写语义骨架 |
| 换品牌后仍完全成立 | 阶段2或3 | 重审品牌角色与产品锚 |
| 押韵破坏动作或自然语序 | 阶段4 | 去除强押，语义优先 |
| slogan音步无意失衡 | 阶段4 | 调整槽位、词长、停顿或承认有意破格 |
| 长文案只有情绪没有因果 | 阶段3 | 重建人物动作与品牌落点 |
| 社媒文案伪装真实体验 | 阶段4 | 补披露、事实边界和真实摩擦 |
| 技术通过被当作内容通过 | 阶段5 | 恢复人工内容状态 |

## 12. 方法卡调用位置

| 阶段 | 可调用的问题 | 必须留下的本次产出 |
| --- | --- | --- |
| 命题 | 约束拆解、事实与暗示边界 | 命题合同和主张表 |
| 研究 | 人群张力、品牌关键词、场景任务 | 语言任务句 |
| 方向 | 属性转译、关系视角、语义联想 | 机制不同的方向卡 |
| 多稿 | 语义压缩、结构适配、信息顺序 | 结构不同候选 |
| 评审 | 品牌不可替换、表达一致性、声音层 | 逐稿人工记录与采用/拒绝理由 |

方法卡生效的证据是它改变了具体语义、结构或评审决定，不是清单中出现了方法卡ID。对仗和押韵属于短文案的声音层，不需要为每次局部修复新增方法卡。

## 13. 最小运行证据链

运行清单用`run_scope`区分证据范围。`concept-only`完成命题、子类型与方向门；`production-candidate`再完成候选稿、语义品牌、文体及适用的声音门；`delivery-candidate`另完成最终文本、技术门；AIGC记录与平台申报仅交付后提醒。当前范围内的质量门必须通过或有边界通过，后续质量门必须为`not-run`；正确停在前一范围不是残缺运行，也不得继承后续通过状态。

一次完整方法运行至少能定位到：

- 命题证据与约束JSON；
- 可用事实、禁用主张、工作子类型和开放项；
- 研究笔记或语言领地判断；
- 实际成立的方向及采用/拒绝理由；
- 方法卡本次应用结果；
- 1–5份通过内部筛选的候选；
- 逐稿人工内容评审；
- slogan/short-copy的声音评审；
- 与入选候选一致的最终文本；
- 技术验证、交付后的AIGC记录/平台申报提醒、运行状态和文件哈希。

产物可以按简单任务合并，但语义、品牌、声音和技术结论必须可区分。共享方法完整走通可记录 `method_validated`，现有清单可继续使用 `method_run_complete: true`。作品完成以`delivery_complete`为准；报名、许可手续、AIGC/平台申报及上传不构成作品未完成。

## 新运行的版本与审核绑定

新运行使用0.4.0运行清单，并执行[版本与审核合同](../../workflow/version-bound-review.md)：生产调用前运行校验，绑定真实决定、作品哈希和覆盖范围；交付时核对最终对象与跨文件状态。已有明确生产授权直接复用，生产授权不能替代最终内容批准。旧清单保持历史口径，不能自动宣称通过新合同。

## 按需冲奖与挑战稿

用户明确追求更高奖级时执行[上限诊断与挑战稿协议](../../workflow/award-ceiling-and-challengers.md)，先定位失分责任层，允许保留已批准文本或方案；模拟评审不代表真人或奖级保证。
