# 营销策划：证据到行动作业系统

本 Playbook 用于大广赛策划案、学院奖营销策划及命题允许的相近整合营销方案。先读取[公共内核](../../workflow/common-competition-kernel.md)和[反卡片化设计门](../../workflow/content-shaped-layout-gate.md)，再读取当前赛事配置、[营销策划交付规范](../../deliverables/marketing-plan.md)和对应提交 profile。

它规定策划怎样成立、何时继续、何时回退。文件尺寸、页数、上传字段和技术命令不在本文件重复。

## 1. 策划案成立条件

营销策划不是活动名称集合，也不是把调研、品牌屋、Big Idea、媒介、预算等栏目填满。它必须形成一条可复核的决策链：

`事实分层 → 决策问题 → 具体人群/场景/矛盾/任务 → 品牌与产品角色 → 策略中介 → 核心主张与 Big Idea → 内容和活动机制 → 媒介与购买闭环 → 预算与验证`

链条上的每个结论都应说明：

- 它回答什么问题；
- 由什么证据或上一步判断支持；
- 排除了什么替代解释；
- 它向下一步交付什么约束。

命题未要求的模块不为凑形式强制加入；一旦正文使用外部数据、调研结论、预算或 KPI，仍必须满足证据、算术和测量定义。

## 2. 运行阶段与高成本边界

| 阶段 | 主要产出 | 未通过时不得进入 |
| --- | --- | --- |
| 0. 命题、环境与事实底座 | 生图能力前检、命题约束、官方资产表、事实/主张边界 | 方向承诺；能力缺失时须先取得用户选择 |
| 1. 研究 | 研究问题、证据登记、研究缺口、反证 | 洞察定稿 |
| 2. 洞察与方向 | 人群—场景—矛盾—任务、3–5个策略方向 | 策略模型和创意生产 |
| 3. 策略中介 | 品牌角色、产品RTB、策略中介、核心主张 | Big Idea与活动展开 |
| 4. 机制工程 | Big Idea、内容、活动、媒介、转化、预算/KPI | 高保真样页 |
| 5. 五页内容门 | 五张结构不同的关键样页与人工决定 | 全稿生产 |
| 6. 全稿 | 逐页蓝图、原生母版、人工整本评审 | 最终技术交付 |
| 7. 交付 | 技术验证、运行状态、提交边界 | 完成声明 |

研究与分析可以并行探索，但关键判断必须按依赖关系过门。不得用全稿排版、页面数量或技术通过替代上游内容门。

## 3. 阶段0：命题与事实底座

### 输入

- 官方赛事规则与具体命题；
- 用户提供的官方品牌、产品和陈列素材；
- 当前赛事配置与提交 profile；
- 可核对的品牌、产品、渠道和历史传播材料。

### 必须产出

1. 当前会话的`visual_generation_capability`前检记录；
2. 命题约束记录；
3. `brief-evidence.md` 或等价命题证据表；
4. 官方资产清单：来源、用途、保真要求、许可状态；
5. 可用主张与禁用主张表；
6. 当前研究问题和硬阻塞项。

### 生图能力前检

按公共[视觉生成能力前检](../../workflow/visual-generation-capability-gate.md)检查当前工具。没有或无法确认可调用生图能力时，必须先向用户说明关键视觉、活动/空间/界面样机、五页高保真样稿和整本视觉质量将受严重影响。用户明确接受受限模式后，可以继续研究、洞察、策略中介和低保真结构线框，但不得进入阶段5–7，也不得用纯排版或占位图冒充高保真策划案。

### 检查

- 是否区分赛事要求、品牌事实、产品事实和创作假设；
- 是否把赛事能力上限误当成命题要求；
- 产品利益是否有官方材料支持并保留必要限定；
- 官方素材是否足以承担最终保真元素；
- 是否把“真实提交仍待核对”的事项误作方法运行阻塞。

### 回退或停止

核心品牌/产品身份、关键主张或必须保真的资产无法核实时停止高清生产；其他开放选择进入研究问题，不虚构补齐。

## 4. 阶段1：真实研究与证据分级

### 4.1 先写决策问题

研究问题必须对应后续选择，例如：

- 品类竞争真正发生在产品之间，还是替代工具、习惯或回避行为之间；
- 目标人群在什么场景遇到什么任务；
- 竞品已经占据哪些功能、情绪和文化领地；
- 哪个产品事实能进入可体验或可传播机制；
- 哪种参与和购买摩擦最可能阻断闭环。

“了解年轻人”“看看平台热点”不是可执行的研究问题。

### 4.2 证据层

研究登记至少分开：

- 市场与品类事实；
- 品牌事实；
- 产品事实；
- 竞品产品与传播事实；
- 消费者内容证据；
- 校园、渠道和执行环境事实；
- 策略判断与待验证假设。

每条证据说明能证明什么、不能证明什么、时间、来源、样本边界以及将服务哪个决策。

### 4.3 桌面与平台研究

按问题选择官方资料、权威报告、品牌和竞品公开内容、平台内容、评论与用户任务材料。平台研究遵守：

- 标题和搜索结果只用于建立样本池和议题地图；
- 深读样本应读取正文、字幕、简介、评论、回复、弹幕或可用的完整内容；
- 记录搜索词、时间、结果位、去重数、深读数、内容层、筛选规则和平台限制；
- 同时选择正向、负向、边界和反证样本；
- 高赞、词频、可见评论和公开弹幕只描述样本内部，不外推总体；
- 官方账号低互动只能说明该内容在当前可见样本中的互动有限，不能证明消费者不认知品牌；
- 无法验证用户身份、年龄、真实购买或长期使用时明确保留限制。

若当前洞察依赖一手行为、使用时长、愿付价格或真实购买，应提出访谈、任务观察、日记、问卷或品牌后台数据计划；未执行时保持为研究缺口。

### 4.4 竞品与传播领地

竞品分析不只列品牌和价格。至少比较：

- 产品/服务承诺；
- 可核对的RTB；
- 目标人群和场景；
- 功能、情绪、身份或文化领地；
- 常用内容机制与参与机制；
- 渠道与购买承接；
- 可信优势、空白和不可占领区域。

结论必须指出本品牌应进入、避开或重新定义的领地，而不是停在信息表。

### 研究门

满足以下条件才可定稿洞察：

- 研究问题明确；
- 关键事实已分类并留有来源和边界；
- 消费者证据超越标题层；
- 当前策略判断与事实分开；
- 至少有一项反证检查；
- 研究缺口不会被误写成既成结论。

证据不足时可以提出方向假设，但不得把它标为已验证洞察。

## 5. 阶段2：洞察与策略方向

### 5.1 洞察四元组

一个可进入策略的洞察至少包含：

1. **具体人群**：不是泛称“年轻人”，而是与任务相关的行为或处境分群；
2. **具体场景**：时间、地点、前后动作、关系对象和约束；
3. **真实矛盾**：人想完成什么，同时被什么现实或心理条件阻碍；
4. **未满足任务**：品牌能够帮助完成、退出、降低或重新解释的任务。

推荐句式只作为检查，不进入参赛正文：

> 当___人群在___场景试图___时，他们一方面___，另一方面___；现有方案只解决___，仍未帮助他们___。

洞察必须可以被反驳。记录支持信号、反证、适用边界和需要后续验证的部分。

### 5.2 场景—任务一致性

场景名称必须与真实任务一致：

- 宿舍可能对应共同生活、夜读、空间、噪声、卫生或共享限制，不自动等于送礼；
- 校园不自动等于青春、社团或打卡；
- 节日不自动等于关系表达；
- 平台热词不自动等于参与动机。

如果某个活动或产品动作只能靠重新命名场景才成立，应回到任务层重写。

### 5.3 形成3–5个方向

方向必须使用不同的策略机制，不做同一主题的同义改写。每个方向至少说明：

- 一句话策略；
- 服务的人群、场景与任务；
- 品牌和产品如何介入；
- 核心参与或内容机制；
- 主要渠道和转化路径；
- 证据支持、关键假设与风险；
- 为什么采用或拒绝。

在问题明确后再查询少量受控案例和方法卡。案例只帮助识别机制与失败条件，不替代本命题研究。

### 洞察与方向门

- 洞察四元组完整；
- 方向之间机制可区分；
- 每个方向都能说明产品与品牌角色；
- 入选方向有证据链，不只因为口号好听或视觉好做；
- 被拒方向保留拒绝理由；
- 不把模型推测包装成调查发现。

## 6. 阶段3：品牌角色、产品RTB与策略中介

### 6.1 品牌角色

品牌角色回答“在这个具体矛盾中，品牌凭什么以什么身份出现”。它不是品牌性格形容词，也不是企业使命复述。

检查：

- 是否来自真实品牌资产和命题任务；
- 是否对准未满足任务；
- 换成竞品后是否仍完全成立；
- 是否能够约束内容语气、活动动作和购买承接。

### 6.2 产品RTB

产品RTB区分：

- 官方可核对的功能、结构、成分、规格或服务事实；
- 这些事实对目标任务的意义；
- 可以被用户感知、体验或展示的机制；
- 仍需检测、品牌确认或执行验证的边界。

产品不能只在方案末尾作为包装图出现。它应进入策略中介、Big Idea、参与动作、体验或内容证据和购买路径。

### 6.3 选择策略中介

必须有一页或一组可见结构，把研究结论压缩成后续创意必须服从的决策。模型按问题选择，不机械套用名称：

- 品牌屋：适合表达承诺、利益、角色、RTB和品牌资产的承重关系；
- 痛点—卖点配对：适合逐项证明产品如何解决具体障碍；
- What/How/Why：适合从外在动作进入内在意义；
- 契合阶梯：适合品牌、产品、文化、合作方或受众之间的多层匹配；
- 策略金字塔：适合由事实、选择和原则逐层收束；
- 用户任务或旅程模型：适合说明多个阶段、节点和转换条件。

无论模型名称如何，都必须回答：

- 最终承诺是什么；
- 哪些消费者利益或品牌角色共同支撑它；
- 地基证据与产品RTB是什么；
- 用户如何进入、参与、分享或购买；
- 各层之间为什么成立；
- 它向下一页交付哪些创意约束。

### 6.4 使用品牌屋时

品牌屋同时满足逻辑和视觉要求：

- 屋顶：一句面向消费者的核心承诺或品牌位置；
- 承重结构：功能、情绪、关系或本项目必要的战略支柱；
- 地基：产品RTB、品牌资产、消费者证据和必要限制；
- 入口/路径：进入、参与、分享和购买方式；
- 结构关系：地基支撑支柱，支柱共同支撑屋顶。

不把一组卡片命名为品牌屋。选择建筑式表达时，应有可见屋顶、承重结构和地基；背景只营造品牌世界，通过模糊、遮罩、景深和对比控制留在语境层。投屏和缩略图下应先读到屋顶与支柱，正文不得因小字、溢出或不自然换行失去可读性。

### 策略中介门

- 上游每项关键证据都有去向；
- 策略判断没有跳过品牌与产品角色；
- 核心承诺由支柱与地基支撑；
- 模型能够约束 Big Idea，而不是装饰总结；
- 换品牌、换产品或删除RTB后，模型不会原样成立；
- 页面结构帮助理解关系，不退化为卡片堆叠。

## 7. 阶段4：核心主张与Big Idea

### 7.1 核心主张

核心主张是策略的最小表达，不等于活动名称。它应同时具备：

- 对准具体矛盾；
- 包含或可自然连接产品利益；
- 与品牌资产一致；
- 能指导内容、体验和购买动作；
- 不依赖开发语言解释。

### 7.2 Big Idea 六问

Big Idea定稿前必须回答：

1. 为什么只能由这个品牌提出；
2. 产品利益如何进入机制，而不只是露出；
3. 品牌资产、文化或识别如何发挥作用；
4. 用户为什么愿意参与；
5. 用户为什么愿意生成或传播内容；
6. 内容、校园体验、渠道与购买如何闭环。

若其中任一关键问题只能回答“因为我们做一个话题/挑战/快闪”，说明机制仍为空。

### 7.3 内容机制

内容不是平台清单。每条核心内容线至少说明：

- 谁在什么情境下说什么；
- 使用何种内容母题、栏目或叙事结构；
- 产品和品牌如何可见地参与；
- 观众下一步做什么；
- 内容如何沉淀为模板、脚本、界面、UGC、测试结果或可复用资产；
- 正向吸引力与真实摩擦如何同时呈现；
- 哪些声称、隐私、医疗、肖像或平台风险需要控制。

平台角色、栏目、标题样例、内容结构和承接页应具体到可以继续制作，而不是只写“在小红书种草、B站科普、抖音引爆”。

## 8. 活动机制工程

核心活动不能只有名称、阶段和四步流程。每个活动至少形成以下运行说明：

- 活动目的及其对应策略任务；
- 时间、地点、参与对象与容量；
- 参与条件和完整规则；
- 用户进入、行动、退出和异常路径；
- 品牌、工作人员、合作方和渠道各自的动作；
- 空间平面、装置、界面或服务蓝图；
- 所需产品、物料、内容模板和数据字段；
- 即时反馈、奖励或权益；
- 产生的内容资产及审核方式；
- 后续内容、社群、渠道、试用或购买承接；
- 人员职责、审批、卫生、安全、隐私、法务和停止条件；
- 数量与成本驱动；
- KPI定义、分母、数据源和测量时间。

空间示意、界面流程、内容样机和物料不是装饰，它们是“方案可执行”的证据。核心活动至少提供一种可审查的执行样机。

### 执行一致性检查

- 场景是否匹配真实任务；
- 参与规则能否让陌生执行团队复述；
- 每一步是否有明确主体和下一站；
- 连接线、流程方向和分支是否清晰；
- 用户是否获得即时价值，而非只替品牌生产内容；
- 产生的内容是否有发布、审核、复用与回流路径；
- 活动是否能在没有口头补充的情况下估价和排期。

## 9. 媒介、渠道与购买闭环

媒介计划从用户旅程和活动资产推出，不按平台平均分配。至少说明：

- 每一阶段的传播目标；
- 目标人群和触达场景；
- 内容或活动资产；
- 平台、校园、门店、电商或私域角色；
- 用户动作与下一站；
- 频次、时间和资源假设；
- 试用、咨询、领取、加购、购买、复购或反馈入口；
- 数据如何回传并用于下一轮调整。

流程图只保留必要连线。多个渠道共同回流时，先建立单一主路径，再用标注表达条件，避免交叉线制造视觉噪音。

## 10. 预算、KPI与验证

### 预算

预算不是数字填空。每项支出至少关联：

- 阶段和策略任务；
- 具体活动、内容、媒介或物料；
- 数量、单价和计算公式；
- 报价来源、估算依据或待询价状态；
- 预备金、税费或平台费用口径；
- 与总预算的算术关系。

没有真实报价时明确标为规划模型，不冒充供应商确认价格。

### KPI

每个指标至少定义：

- 指标名称和业务含义；
- 分子与分母；
- 数据源与采集责任；
- 测量时间窗口；
- 基线、目标或决策阈值；
- 失败后调整什么；
- 不能由该指标证明什么。

曝光、互动、参与、内容产出、渠道动作和购买结果分层，不能用曝光量证明洞察或转化。目标值是验证计划，不写成已取得效果。

## 11. 逐页蓝图

开始全稿前，为每页记录：

- 页面标题；
- 本页唯一任务；
- 证据或上游输入；
- 需要呈现的具体内容；
- 本页结论；
- 与前一页、后一页的关系；
- 建议版式；
- 正文、附录或删除归属。

每页完成一次推进：提供事实、压缩矛盾、作出选择、解释机制或证明可执行。目录、路线图和阶段排期只有在提供阅读地图时才保留；不为凑页数制造章节页、空白页、重复总结或把一段话拆成多页。

“建议版式”必须先写本页的内容关系，再写结构选择。数据、因果、流程、空间、时间、对比、预算和关键视觉分别使用与任务匹配的图表、结构图、路径、平面/场景、节奏、表格或完整画面，不得统一写成“卡片网格”。确需真实界面或离散同级项目卡片时，按反卡片化设计门记录语义角色、范围、非卡片替代和评审证据。

### 正文与附录

正文保留：

- 对当前决策必要的事实和限制；
- 洞察、策略中介、Big Idea和执行闭环；
- 能证明活动可执行的样机、路线、预算与指标。

附录保留：

- 样本池、完整来源、问卷和访谈题项；
- 评论、回复、弹幕、字幕或编码明细；
- 详细计算、报价、合规和方法说明；
- 需要复核但不应打断正文叙事的证据。

完全删除：

- 内部方法卡编号和工作流说明；
- 重复事实、无结论数据墙和纯装饰章节页；
- 无证据的调查口吻；
- 与策略和执行无关的通用趋势；
- 技术验证、版本迭代和AI工作过程。

## 12. 五页内容质量门

全稿前先制作五张高保真原生PPTX样页：

1. 核心研究/洞察页；
2. 策略推导页；
3. 品牌屋或等价策略中介页；
4. Big Idea页；
5. 核心活动机制页。

五页必须分别采用适合内容关系的结构，不能使用同一模板换文案。统一品牌色、字体和识别资产，不等于统一骨架。

五页不得默认采用网页首页、仪表盘、玻璃拟态面板或重复圆角卡片。局部例外必须具有真实界面/物件或内容关系语义；无法说明时，在进入全稿前按页面任务重建。

### 人工评审问题

- 洞察是否有具体人群、场景、矛盾、任务和诚实边界；
- 从洞察到策略是否有中介，是否存在跳步；
- 品牌和产品是否不可替换；
- Big Idea是否包含产品、品牌资产、参与、传播和购买；
- 活动是否达到可运营、可估价、可度量的颗粒度；
- 官方资产是否经过专业转译而非直接陈列；
- 五页是否具有不同的信息结构和清晰阅读路径；
- 缩略图和投屏下是否仍能读出主结论；
- 是否存在卡片化、小字、溢出、自然换行失败、线条混乱或背景抢字。

人工决定为“通过”“有条件通过”或“退回重做”。未明确通过或未完成条件整改时，不进入全稿生产。技术校验只说明样页文件没有结构故障。

## 13. 全稿生产与人工质量门

### 原生母版

PPTX作为可编辑母版时：

- 文字、表格、路线图、预算、KPI和策略模型使用原生对象；
- 官方资产承担真实性；
- 生成或编辑视觉只承担允许的情境和氛围；
- 页面结构随数据、画像、模型、路线、活动、空间、内容、预算和附录角色变化；
- 正文密度由决策任务决定，不用空白或卡片掩盖内容不足；
- 单页局部修复不机械复制到全稿。

### 整本人工质量门

至少检查：

- 逐页任务、证据、结论和交接是否连续；
- 研究是否收束成策略，而非平铺资料；
- 品牌、产品和RTB是否贯穿策略、创意和执行；
- 活动、内容、媒介、渠道、购买和测量是否闭环；
- 页面版式是否服务内容，不是统一卡片模板；
- 卡片、面板或标签是否只在有真实对象/内容关系语义时局部出现，并有例外记录；
- 字号、换行、对比、背景、线条、图表和资产位置是否在投屏与缩略浏览下有效；
- 场景、人物、动作和渠道是否逻辑一致；
- 前台是否清除内部开发语言；
- 正文与附录是否分工；
- 预算、KPI、授权和研究边界是否诚实。

用户指出可观察问题时，记录问题影响的页面和逻辑层，回到最近责任阶段修复。不得只处理表面样式，也不得把一页的修复泛化为整本模板。

## 14. 技术检查边界

内容人工门通过后，按交付规范和赛事 profile 检查文件。技术工具可以验证：

- 文件存在、可打开和包结构；
- 页数、尺寸、分辨率、颜色模式和文件大小；
- 对象越界、缺字、字体或重导入问题；
- manifest字段、路径和哈希；
- 预算算术、KPI字段、AIGC使用声明和必要记录；
- 赛事要求的正文、附件和上传字段。

技术工具不能证明：

- 研究代表性或洞察真实性；
- 策略必然性、品牌独占性或创意质量；
- 活动可执行性、报价真实性或KPI合理性；
- 视觉高级、语言得体或评委会认可；
- 素材已获得真实投稿许可。

## 15. 硬停止与回退表

| 发现 | 回退位置 | 处理 |
| --- | --- | --- |
| 模型推测被写成调研结论 | 阶段1 | 降级为假设或补研究 |
| 当前环境没有可调用生图能力且用户尚未明确选择 | 阶段0 | 告知严重质量影响，等待启用/切换环境或受限模式选择 |
| 用户接受无生图受限模式却进入五页或全稿生产 | 阶段0 | 退回`concept-only`，保持内容生产与交付阻塞 |
| 平台证据只有标题 | 阶段1 | 深读内容、评论、回复或弹幕并记录边界 |
| 洞察缺人群、场景、矛盾或任务 | 阶段2 | 重写四元组，不进入策略 |
| 场景与真实任务不匹配 | 阶段2 | 回到任务分析，不只改场景名称 |
| 从洞察直接跳活动 | 阶段3 | 补品牌/产品角色和策略中介 |
| 品牌屋只是卡片或装饰建筑 | 阶段3 | 重建承重逻辑和信息层级 |
| Big Idea换品牌仍成立 | 阶段3或4 | 重审品牌角色、RTB和机制 |
| 活动只有名称和四步流程 | 阶段4 | 补完整运行、资产、人员、风险、渠道与测量 |
| 五页同一模板换文案 | 阶段5 | 按页面任务重建设计结构 |
| 五页或全稿以无语义网页卡片、仪表盘面板或圆角容器作为默认骨架 | 阶段5或6 | 回到逐页任务与内容关系，重建为图表、结构、路径、空间、时间、表格或完整画面；局部例外须留证 |
| 官方资产只是角标或陈列图 | 阶段5或6 | 重做场景、景别和层级整合 |
| 字体溢出、换行异常、线条混乱 | 阶段5或6 | 修正内容结构和版式并重新人工复核 |
| 正文出现命题校正、开发记录或AI过程 | 阶段6 | 移至后台或删除，复核整本语气 |
| 技术通过被当作内容通过 | 阶段7 | 恢复独立人工内容状态，不宣告完成 |

## 16. 方法卡调用位置

| 阶段 | 可调用的问题类型 | 必须留下的本次产出 |
| --- | --- | --- |
| 研究 | 任务分析、竞品领地、证据收束 | 证据如何改变判断 |
| 洞察 | 矛盾压缩、反证、场景任务 | 四元组与边界 |
| 策略中介 | 品牌屋、契合阶梯、痛点—卖点、What/How/Why | 模型结构与向下约束 |
| Big Idea | 主概念贯穿、属性到场景、品牌不可替换 | 六问答案和机制 |
| 活动 | 参与链、内容回传、渠道闭环 | 完整活动工程表 |
| 评审 | 策略执行追踪、表达一致性、对抗式迭代 | 发现、修改与验证记录 |

方法卡被使用的证据是产出了可检查的中间物，而不是 manifest 中出现了卡名。项目专属创意、模型文字和视觉形式不得写回为所有命题的固定要求。

## 17. 最小运行证据链

运行清单用`run_scope`区分证据范围。`concept-only`完成研究、洞察与策略中介门；`production-candidate`再完成五页内容原型、执行工程、逐页蓝图和预算/KPI；`delivery-candidate`另完成整本原生策划案、全稿人工门、技术门和已解析为`yes`或`no`的AIGC使用声明。当前范围内的质量门必须通过或有边界通过，后续质量门必须为`not-run`；正确停在前一范围不是残缺运行，也不得继承后续通过状态。

`quality-gate-results.json`是唯一权威的质量门状态。运行清单不再维护另一套`quality_gates`摘要；展示层需要摘要时应从正式七道门结果派生，不能手工录入第二份状态。

一次完整方法运行至少能定位到：

- 命题约束与命题证据；
- 研究问题、证据登记、样本边界与研究缺口；
- 3–5个方向及采用/拒绝理由；
- 洞察四元组、品牌角色、产品RTB和策略中介；
- Big Idea、内容与活动工程、媒介转化；
- 预算/KPI契约（命题要求或方案使用时）；
- 逐页蓝图；
- 五页人工内容决定；
- 全稿人工质量决定；
- 技术验证、AIGC使用声明及必要记录和最终状态。

这些证据可以按项目复杂度合并文件，但不能用一个“通过”字段替代其实际内容。只有共享方法完整走通并留下证据时，才能将 `method_validated` 记为真；现有运行清单可继续使用等价字段 `method_run_complete: true`。真实报名、许可和上传未完成时，`submission_ready` 仍为假。

## 最终像素证据

生产代表稿与最终交付必须执行[最终像素与多尺度审核](../../workflow/final-pixel-review.md)，绑定实际目标渲染、缩略/原尺寸/局部视图和当前文件哈希；逐项核对文字、来源、标签容器、产品空间、裁切与残留，保留有内容依据的设计例外。技术规格通过不能替代视觉判断。

## 按需冲奖与挑战稿

用户明确追求更高奖级时执行[上限诊断与挑战稿协议](../../workflow/award-ceiling-and-challengers.md)，先定位失分责任层，允许保留已批准文本或方案；模拟评审不代表真人或奖级保证。
