# 平面广告：视觉说服作业系统

默认完成边界：交付作品。当前赛事规则、实际提交规格与外部研究引用在完成前核对；素材/字体使用依据、AIGC后台记录及平台申报仅完成后提醒，报名身份、上传和回执不阻断作品完成。
本 Playbook 用于大广赛平面广告与学院奖平面作品。先读取[公共内核](../../workflow/common-competition-kernel.md)和[反卡片化设计门](../../workflow/content-shaped-layout-gate.md)，再读取当前赛事配置、[平面广告交付规范](../../deliverables/print-ad.md)和对应提交 profile。

它规定如何让一个品牌特有的判断通过视觉关系在短时间内成立。尺寸、分辨率、文件格式、数量和上传字段不在本文件重复。

## 1. 平面作品成立条件

平面广告不是一张装饰品牌和产品的漂亮图。它必须形成：

`传播任务 → 人群矛盾 → 品牌/产品角色 → 单一视觉判断 → 可见关系 → 构图证据 → 文案协同 → 系列递进`

观众应先看到关系，再得到判断，最后确认品牌。作品如果只能靠创意说明、角落小字或作者口头解释才能成立，视觉说服尚未完成。

## 2. 运行阶段与高成本边界

| 阶段 | 主要产出 | 未通过时不得进入 |
| --- | --- | --- |
| 0. 命题、环境与资产底座 | 生图能力前检、命题证据、产品/Logo/文字资产、传播任务 | 视觉方向承诺与高清生产；能力缺失时须先取得用户选择 |
| 1. 研究与视觉领地 | 竞品同质化、案例机制、受众场景 | 高保真创意 |
| 2. 四方向 | 机制不同方向与采用/拒绝理由 | 高清生产 |
| 3. 低成本视觉原型 | 动作、因果、比例、阅读顺序和误读测试 | 最终生成与合成 |
| 4. 分层生产 | 无字视觉层、官方资产、确定性文字 | 最终系列 |
| 5. 系列与人工视觉门 | 单幅成立、系列递进、三秒与替换测试 | 技术导出 |
| 6. 技术交付 | 尺寸、模式、分辨率、格式、哈希与AIGC | 完成声明 |

高分辨率生成、复杂合成和整套导出属于高成本生产。视觉关系原型未通过前，不应用高清画面掩盖概念问题。

## 3. 阶段0：命题、传播任务与资产底座

### 必须产出

1. 当前会话的`visual_generation_capability`前检记录；
2. 命题证据与硬约束表；
3. 一句单一传播任务；
4. 产品、Logo、包装、品牌规范和必须文字的官方资产清单；
5. 可用产品事实、命题方主张、禁用表达和必要限定；
6. 单幅/系列、数量、场景与特殊奖项边界；
7. 当前硬阻塞与仅影响真实提交的事项。

### 生图能力前检

按公共[视觉生产路径前检](../../workflow/visual-generation-capability-gate.md)检查直接工具、外部生成回传或充分的已提供资产；按[工具与宿主适配](../../workflow/image-tool-adaptation.md)准备实际输入。外部执行不是低保真模式；等待所需图像时继续独立工作，不宣称视觉生产完成。回传核验后继续相应原型或生产，仍经过既有内容与交付检查。确实无路径时说明具体影响并取得最小选择，不能静默用占位图替代。

### 单一传播任务

后台任务句至少明确：

> 让___人群在___场景，一眼看见___关系，从而相信___品牌判断。

如果一句话同时要求解释多个利益、多个受众和多个动作，先确定主次，不把所有命题词塞进一张画面。

### 资产可生产性

进入高清生产前确认：

- 官方产品图和Logo来源明确；
- 产品视角和清晰度足以支持选定构图；
- 必须保真的包装文字不依赖模型生成；
- 产品无法被可靠合成时，方向不依赖虚构几何或标签；
- 生成图只承担公共内核允许的情境和视觉层。

## 4. 阶段1：受控研究与视觉领地

研究回答具体视觉问题：

- 品类画面已经拥挤在哪些符号、场景、颜色和构图；
- 受众在哪个真实动作或瞬间遇到矛盾；
- 产品事实能否变成可见动作、因果、对比或转换；
- 品牌资产能否进入画面机制，而不是只做装饰；
- 常见创意为什么会被误读或变成换品牌也成立。

从受控案例中只读取机制和失败边界。逐件定向复核可见页面，剔除观察模板化、品牌可替换、方法误配和证据越界记录。案例图不作为生成模型的风格模板，也不复制原作构图、符号、文案或配色。

### 同质化风险图

至少登记：

- 品类常见视觉套路；
- 当前命题高频符号；
- 竞品已占领的功能或情绪表达；
- 容易造成误读、尴尬或合规问题的视觉；
- 可进入但必须重新定义的品牌资产。

研究结论必须改变方向选择，不能只做案例展示墙。

## 5. 阶段2：形成四个真正不同的方向

后台默认探索四个机制方向并保留取舍，前台默认最多三个入围方向供选择；两者数量口径不同。命题极窄时可减少并说明理由，用户明确要求的数量优先，不补造弱方向。

每个方向至少说明：

- 一句话人群矛盾；
- 一句话传播判断；
- 核心视觉对象；
- 对象之间的动作、因果、对比、转换或尺度关系；
- 产品为何不可替换；
- 品牌资产如何进入机制；
- 单幅或系列规则；
- 最大误读、合规和制作风险；
- 低成本验证办法；
- 方法卡的本次输入、步骤、可观察输出与失败条件。

方向差异必须来自洞察、因果或视觉机制，不能只是换背景、风格、颜色、摄影质感或标题。同一创意仍可比较不同视觉风格；风格比较不冒充新的创意方向。按[视觉风格选择](../../workflow/visual-style-direction.md)在生图前明确图片面貌，不默认像真实照片。

### 方向门

- 视觉判断能够用一句话复述；
- 产品不是事后贴入；
- 品牌资产参与意义形成；
- 后台方向的对象关系明显不同，前台只展示入围比较所需内容；
- 风险和误读有可执行测试；
- 至少保留一个拒绝方向及理由。

## 6. 阶段3：低成本视觉原型

先用草图、原生形状、拼贴或低分辨率概念图测试关系。原型不追求最终质感，必须回答：

- 第一眼看到什么；
- 第二眼理解什么动作或因果；
- 产品在关系中做什么；
- 品牌通过什么被确认；
- 文案补充什么，而不是解释什么；
- 画面最可能被误读成什么；
- 系列中哪些不变量和变量可持续。

### 三类原型测试

1. **视觉先行测试**：遮住标题和说明，只看视觉能否识别核心关系；
2. **产品先行测试**：只保留产品和主要关系，能否说明产品为何在场；
3. **缩略图测试**：在接近评审浏览尺寸下，主焦点、动作和品牌确认是否仍清楚。

形式隐喻存在但动作或双方关系不可读时，方向失败。不要用更多解释性小字修补。

### 内容形态与卡片例外检查

原型先用主体、动作、因果、比例、空间、材质、留白和阅读顺序建立画面，不从圆角信息盒、UI 面板、仪表盘或卡片网格开始。去掉容器边框后若只剩若干互不作用的文字块，说明卡片正在替代视觉关系，方向应回到原型重建。

只有作品真实表现界面、票券、商品卡等对象，或卡片确实表达离散同级、边界、归属或交互状态时，才可局部保留，并记录语义角色、范围、非卡片替代方案和缩略图/三秒评审证据。整齐、科技感、易对齐或方便生成都不是成立理由。

## 7. 阶段4：分层生产

按公共内核执行官方资产、生成视觉和确定性对象的职责分离。

### 生产顺序

1. 固化视觉判断、对象关系、视线、比例、产品作用和Logo位置逻辑；
2. 生成或制作无最终文字、无Logo、无伪包装的视觉底层；
3. 按所选风格检查造型、空间、纹理与边缘完成度，区分有意夸张和无意错误；摄影物理标准仅用于需要真实摄影感的部分；
4. 使用官方产品、包装与Logo保真合成；
5. 用确定性排版加入标题、必要信息和限定；
6. 从原始输入或足够分辨率的制作文件完成高清稿，不放大概念预览图；
7. 保存提示词、工具信息、初始生成、拒绝样本、选择和修改记录。

局部修订先继承已经认可的视觉机制、元素和语言，将本轮变化绑定到具体画面或原句；修改后同时核对累积要求。反馈“调整曲线表现”不能自动解释为删除曲线，“增补浪花”不能替换已经认可的路线。该原则不限于这些对象，具体项目按实际关系记录。

### 产品整合检查

- 产品的尺度、边缘、色彩及构图关系是否融入所选视觉语言；写实部分再检查光线、透视、接触阴影和景深，插画或拼贴不因缺少这些摄影特征自动失败；
- 产品尺寸和位置是否支持传播判断；
- 产品是否被裁切、遮挡或缩小到只剩角标；
- 包装文字、Logo和比例是否保持官方真实性；
- 产品在系列中的位置变化是否有叙事理由；
- 画面是否仍可被其他品牌产品无缝替换。

### 文字与信息层级

- 标题承担判断，不承担解释全部视觉；
- 品牌、产品、必要限定和参赛必备文字各有稳定层级；
- 小字只保留法定或必要信息；
- 中文、数字和标点使用确定性排版；
- 不用底板、描边、渐隐或阴影作为全局默认补丁；
- 不用重复圆角容器、悬浮面板或网页式卡片作为通用构图骨架；
- 每项可读性修复只应用于实际发生冲突的区域。

## 8. 系列系统

系列先声明：

- **不变量**：传播判断、核心机制、产品/Logo规则、字体系统、色彩家族和阅读顺序；
- **变量**：场景、人物、动作、对象、视角、证据或叙事步骤；
- **信息增量**：每幅为整体新增什么；
- **单幅成立条件**：脱离系列时仍能读懂核心关系和品牌。

新正式运行将方向判断保存为`series_plan`：`mode`、计划`units`、选择`reason`、`user_requested_series`，系列另含`shared_mechanism`；成员增量沿用下表，不另造平行记录。单幅须有当前命题、用户范围或无有效增量的具体理由；赛事上限不是单幅优先依据。代表稿通过后完成已授权成员；不同方向各自判断，不继承上一个方向的单幅豁免。最终清单与计划成员一致后才可交付，创意增量仍由实际画面及真实内容判断支持。

## 9. 人工视觉质量门

### 9.1 三秒理解测试

让未参与创作的人在短时观看后回答：

- 第一眼看到了什么；
- 发生了什么；
- 作品想让我相信什么；
- 记住了哪个品牌或产品；
- 哪个元素造成困惑。

测试记录真实回答，不用引导性问题教受众理解。若无法招募外部测试，至少制作盲测板并记录当前限制，不把创作者自评当成用户验证。

### 9.2 去品牌与换产品测试

- 去掉品牌后，视觉关系是否仍可理解；
- 恢复品牌后，品牌是否显著改变意义；
- 换成竞品或通用产品后，创意是否仍无损成立；
- 如果能替换，缺少的是产品机制、品牌资产还是具体场景。

“去品牌仍看懂”并非失败；失败是品牌恢复后没有增加任何专属意义。

### 9.3 全尺寸与缩略图检查

- 缩略图：主焦点、动作、品牌和系列节奏；
- 全尺寸：文字、边缘、合成、包装、法定信息和生成瑕疵；
- 联系表：三幅共同机制、产品权重和信息递进；
- 单幅：脱离系列后的独立理解。

### 9.4 人工评审问题

1. 传播任务是否单一；
2. 视觉关系是否明确，不靠说明成立；
3. 产品是否参与因果或转换；
4. 品牌是否不可替换；
5. 文案是否与视觉分工；
6. 系列是否有真实变量和信息增量；
7. 官方资产是否保真且融入空间；
8. 生成视觉是否有假字、假Logo、伪包装、物理或人体错误；
9. 构图、对比、视线和留白是否支持阅读顺序；
10. 可读性修复是否局部、必要且没有制造新噪音；
11. 是否存在伦理、隐私、羞辱、刻板印象或合规风险；
12. 作品在目标尺寸和评审场景下是否仍成立。
13. 画面结构是否由视觉关系而非无语义卡片、UI面板或仪表盘骨架支撑；若有局部卡片，例外理由是否成立。

凡画面含对白、人物口语或拟人发言，另做一次脱离策略术语的朗读检查：把角色、表情和场景说清后直接读出句子；若句子更像流程分类、命题解释、公益教育口径或为了对称而写的问答，就退回确定性文案层。策略词可以存在后台，但不能原样充当人物会说的话。标题负责收束判断，对白只承担当下动作或回应，二者不得重复解释画面。

## 10. 技术检查边界

人工视觉门通过后，按交付规范与赛事 profile 检查：

- 文件格式、尺寸、方向、分辨率、颜色模式和大小；
- 系列数量与文件命名；
- 图像可打开、通道和元数据；
- 交付后的AIGC记录/平台申报提醒、来源manifest和文件哈希；
- 只选择实际提交文件，不把联系表或预览图计入作品数量。

机器不能判断视觉关系、品牌不可替换、产品是否自然融入、构图是否高级、系列是否有意义、生成物理是否可信或三秒是否理解。技术通过不产生人工内容通过。

## 11. 硬停止与回退表

| 发现 | 回退位置 | 处理 |
| --- | --- | --- |
| 产品、Logo或核心品牌身份没有官方证据 | 阶段0 | 停止高清生产，补资产或改方向 |
| 没有直接生图能力、可行外部路径或充分资产且用户尚未选择 | 阶段0 | 说明具体影响，复用已有决定或取得启用/外部回传/受限模式的最小选择 |
| 用户接受无生图受限模式却进入高清生产 | 阶段0 | 退回`concept-only`，不得形成成稿、内容通过或交付声明 |
| 传播任务包含多个同级主张 | 阶段0 | 确定主次并重写任务句 |
| 四方向只是换风格或颜色 | 阶段2 | 重做视觉因果和对象关系 |
| 视觉只能靠大段解释理解 | 阶段3 | 重做原型，不加说明小字 |
| 主要构图依赖无语义卡片网格、UI面板或仪表盘外壳 | 阶段3 | 删除模板骨架，按主体动作、因果、空间和阅读顺序重做原型；真实界面例外须留证 |
| 双方动作或因果过于抽象 | 阶段3 | 显化动作、对象、方向或结果 |
| 生硬数字或符号压过产品和文化逻辑 | 阶段2或3 | 取消强行概念，回到任务与品牌资产 |
| 生成层出现假字、假Logo或假包装 | 阶段4 | 删除生成元素，使用无字层和官方资产 |
| 产品像后贴角标或可被竞品替换 | 阶段4 | 重做产品作用、空间和视觉语法 |
| 系列只换标题或背景 | 阶段5 | 重做变量和信息增量 |
| 系列每幅完全异构 | 阶段5 | 恢复共同机制和识别规则 |
| 局部修复被复制成全局噪音 | 阶段4或5 | 只保留有证据的局部修复 |
| 技术通过被当作创意通过 | 阶段6 | 恢复人工视觉状态 |
| 策略分类词被直接写成人物对白 | 阶段4或5 | 保留策略结构，重写为场景中可自然说出的具体动作语言并朗读复核 |

## 12. 方法卡调用位置

| 阶段 | 可调用的问题 | 必须留下的本次产出 |
| --- | --- | --- |
| 命题 | 约束拆解、单一传播任务 | 任务句与硬约束表 |
| 研究 | 同质化、符号风险、场景动作 | 视觉领地和风险图 |
| 方向 | 同构、转译、联想、因果、尺度 | 四个机制不同方向 |
| 原型 | 三秒理解、误读、品牌替换 | 低成本原型与测试记录 |
| 生产 | 无字生成、官方资产、确定性排版 | 分层制作和来源记录 |
| 系列 | 不变量、变量、信息增量 | 系列矩阵 |
| 评审 | 对抗式检查、局部修复 | 观察—影响—修改—验证记录 |

方法卡生效的证据是它形成了可见关系、生产约束和失败判据，并能追溯到原型、提示词、取舍和成稿。方法名称本身不是应用证据。

## 13. 最小运行证据链

运行清单用`run_scope`标明证据范围：`concept-only`只要求命题、方向、概念门、质量门结果和状态；`production-candidate`再要求官方资产、生产、人工视觉、技术；AIGC记录与平台申报仅交付后提醒；`delivery-candidate`另要求最终交付manifest。正确停在概念门不是残缺运行，但不得继承后续关卡的通过状态。

运行清单用`method_validation_status`区分普通创作与方法验证。`not-claimed`不强制方法证据；只有声明`method-validated`时，才必须登记`method_cards_used`、`method_cards_rejected`和`method_application`，且应用记录要能定位每张已用方法卡如何改变视觉关系、生产约束或取舍。方法卡ID本身不能充当验证证据。

一次完整交付范围的方法运行至少能定位到：

- 命题证据、传播任务和官方资产清单；
- 受控研究、同质化风险和参考采用/剔除理由；
- 四个机制不同方向及选择理由；
- 方法卡本次输入、步骤、输出和失败条件；
- 低成本原型与三类原型测试；
- 生成提示、初始与拒绝样本；
- 官方资产合成和确定性排版来源；
- 系列不变量、变量和信息增量矩阵；
- 三秒、去品牌/换产品、缩略图与全尺寸人工检查；
- 技术验证、交付后的AIGC记录/平台申报提醒、manifest、最终文件和运行状态。

简单任务可以合并记录文件，但不得省略视觉关系、品牌归属、系列递进和人工检查的实际证据。共享方法完整走通可记录 `method_validated`，现有运行可继续使用等价状态。作品完成以`delivery_complete`为准；报名、许可手续、AIGC/平台申报及上传不构成作品未完成。

## 最终像素证据

生产代表稿与最终交付必须执行[最终画面验收](../../workflow/final-pixel-review.md)，绑定实际目标渲染与当前文件哈希，覆盖全部适用页面并主动核验关键内容；仅在看不清或有实际疑点时补局部视图和对象测量，不要求逐对象建档。保留有内容依据的设计例外。技术规格通过不能替代视觉判断。
