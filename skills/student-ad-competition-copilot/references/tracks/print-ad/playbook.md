# 平面广告：视觉说服作业系统

默认完成边界：交付作品。当前赛事规则、实际提交规格与外部研究引用在完成前核对；素材/字体使用依据、AIGC后台记录及平台申报仅完成后提醒，报名身份、上传和回执不阻断作品完成。
本 Playbook 用于大广赛平面广告与学院奖平面作品。先读取[公共内核](../../workflow/common-competition-kernel.md)和[反卡片化设计门](../../workflow/content-shaped-layout-gate.md)，再读取当前赛事配置、[平面广告交付规范](../../deliverables/print-ad.md)和对应提交 profile。

它规定如何让一个品牌特有的判断通过视觉关系在短时间内成立。尺寸、分辨率、文件格式、数量和上传字段不在本文件重复。

## 1. 平面作品成立条件

平面广告不是一张装饰品牌和产品的漂亮图。它必须形成：

`传播任务 → 人群矛盾 → 品牌/产品角色 → 单一视觉判断 → 可见关系 → 构图证据 → 文案协同 → 系列递进`

观众应先看到关系，再得到判断，最后确认品牌。作品如果只能靠创意说明、角落小字或作者口头解释才能成立，视觉说服尚未完成。

## 2. 运行阶段与高成本边界

| 阶段 | 主要产出 | 未通过时不得进入 |
| --- | --- | --- |
| 0. 命题、环境与资产底座 | 生图能力前检、命题证据、产品/Logo/文字资产、传播任务 | 视觉方向承诺与高清生产；能力缺失时须先取得用户选择 |
| 1. 研究与视觉领地 | 竞品同质化、案例机制、受众场景 | 高保真创意 |
| 2. 创意方向 | 机制不同方向与采用/拒绝理由 | 高清生产 |
| 3. 低成本视觉原型 | 动作、因果、比例、主要文字设计、阅读顺序和误读测试 | 最终生成与合成 |
| 4. 视觉与文字制作 | 既定图文设计、官方资产、按需分层制作与准确信息 | 最终系列 |
| 5. 系列与人工视觉门 | 单幅成立、系列递进、传播理解与替换检查 | 技术导出 |
| 6. 技术交付 | 尺寸、模式、分辨率、格式、哈希与AIGC | 完成声明 |

高分辨率生成、复杂合成和整套导出属于高成本生产。视觉关系原型未通过前，不应用高清画面掩盖概念问题。

## 3. 阶段0：命题、传播任务与资产底座

### 必须产出

1. 当前会话的`visual_generation_capability`前检记录；
2. 命题证据与硬约束表；
3. 一句单一传播任务；
4. 产品、Logo、包装、品牌规范和必须文字的官方资产清单；
5. 可用产品事实、命题方主张、禁用表达和必要限定；
6. 单幅/系列、数量、场景与特殊奖项边界；
7. 当前硬阻塞与仅影响真实提交的事项。

### 生图能力前检

按公共[视觉生产路径前检](../../workflow/visual-generation-capability-gate.md)检查直接工具、外部生成回传或充分的已提供资产；按[工具与宿主适配](../../workflow/image-tool-adaptation.md)准备实际输入。外部执行不是低保真模式；等待所需图像时继续独立工作，不宣称视觉生产完成。回传核验后继续相应原型或生产，仍经过既有内容与交付检查。确实无路径时说明具体影响并取得最小选择，不能静默用占位图替代。

### 单一传播任务

先从当前命题及所选分支确认：要支持受众的什么行为、减少什么困扰、产品能传达什么价值。任务句简短不证明理解正确；主题字面、其他分支或字体专项不能替换这个目的。出现相反反馈先复查目的，再选新手法；这些判断放进现有方向笔记，不增加用户表格。

后台任务句至少明确：

> 让___人群在___场景，一眼看见___关系，从而相信___品牌判断。

如果一句话同时要求解释多个利益、多个受众和多个动作，先确定主次，不把所有命题词塞进一张画面。

把任务句中的场景落实到首稿提示和原型：人物在什么地方、做什么，产品参与哪一刻？用户已指定场所或使用时机时，童话来源、情绪词和风格参考不替换这一语境；压力发生地与缓冲发生地可以不同，但有意转场须有创意理由。未定项用可撤销假设继续，不新增场景审批。

### 资产可生产性

进入高清生产前确认：

- 官方产品图和Logo来源明确；
- 产品视角和清晰度足以支持选定构图；
- 必须保真的包装文字不依赖模型生成；
- 产品无法被可靠合成时，方向不依赖虚构几何或标签；
- 生成图只承担公共内核允许的情境和视觉层。

## 4. 阶段1：受控研究与视觉领地

当真实界面、职业物件或场景承担识别作用时，先观察必要参考，分清观看端/操作端、真实动作和关键结构，再做原创简化。研究应回答当前不确定性，不复制账号/人物/原评论；历史参考不宣称最新精确版本。

受控检索是词法候选发现，不是语义诊断。保留完整--problem，长中文零命中时提取对象、困扰或目标关键词，用重复--term检索；读取match_details和适用/失败边界。只含来源、验证或负向提及不作为方法推荐。无合格结果可说明缺口后自行推导，不为命中而把问题换成想用的手法。

研究回答具体视觉问题：

- 品类画面已经拥挤在哪些符号、场景、颜色和构图；
- 受众在哪个真实动作或瞬间遇到矛盾；
- 产品事实能否变成可见动作、因果、对比或转换；
- 产品利益怎样决定判断，品牌资产如何准确归属并回应主图；
- 常见创意为什么会被误读或变成换品牌也成立。

从受控案例中只读取机制和失败边界。逐件定向复核可见页面，剔除观察模板化、品牌可替换、方法误配和证据越界记录。案例图不作为生成模型的风格模板，也不复制原作构图、符号、文案或配色。

### 同质化风险图

至少登记：

- 品类常见视觉套路；
- 当前命题高频符号；
- 竞品已占领的功能或情绪表达；
- 容易造成误读、尴尬或合规问题的视觉；
- 可进入但必须重新定义的品牌资产。

研究结论必须改变方向选择，不能只做案例展示墙。

## 5. 阶段2：形成真正不同的方向

### 方法检索必须先发生

顺序为：实际检索 → 保存原始输出和检索取舍记录 → 阅读返回的 steps/诊断/失败边界并形成方向 → 采用。进入此阶段先从 Skill 根目录用已验证的工作区 Python 执行：

```powershell
& "<workspace-python>" scripts/query_case_library.py --kind method --competition "<当前赛事>" --category print-ad --problem "<完整原问题>" --output "<运行目录>/02-direction/method-query-01.json"
```

默认活动包由脚本定位；记录输出的 execution.command、pack、pack_manifest_sha256、started_at/completed_at。显式 --pack 时只用当前活动包，不扩库、不另建检索器。首次空结果原样保留；需要回退时保留同一 --problem，另用重复 --term 保存新的输出，不能覆盖首次结果。

在已有 `02-direction/method-retrieval.json` 写 run_id、recorded_at、original_problem、attempts 和 decisions。每次 attempt 为 output（路径/sha256）、fallback_terms（首次 []）、returned_method_ids（空结果 []）；每个返回方法只写一次 method_id、decision（adopted/rejected）、reason、relation_or_input_change，明确改变了哪个关系或制作输入，拒绝时说明为何排除；全空时 decisions=[] 并写 empty_result_action。字段定义在[现有平面 schema](../../schemas/print-ad-run-manifest.schema.json)的 $defs.method_retrieval。

记录文件真实保存后才采用方向，在运行清单 direction_adoption 写 direction_id、adopted_at 和 method_retrieval 的路径/sha256。所有查询执行完成时间不得晚于 recorded_at，recorded_at 必须严格早于 adopted_at。校验不把事后检索、卡名或自行推导当成检索已发生。新运行沿用清单 0.4.0、使用 creative_contract=print-core-v4、direction_contract=print-direction-v7 与质量门 print-ad.0.16.0；旧 0.1.0—0.13.0 定义和旧认可仍按原合同解释，不能用旧定义登记新合同通过。


按命题和当前不确定性探索有实质差别的机制方向并保留取舍。后台每轮至少写出6个经独立去重后仍真正不同的方向，覆盖至少3类起点：消费者/使用者在命题人群语境里的真实时刻（具体场景或心理）、产品利益/事实、反常识或视角翻转；逐条登记起点类别与具体内容。方法卡可作为任一起点的手段，不能是唯一来源。6是比较下限，不固定总数，也不要求生成6张图。可以多写，不用换背景、标题或补造弱方向凑数；不足时留在本阶段继续推导，不能豁免成单方向自选。前台仍只展示值得判断的少量入围方向，数量服从用户要求和探索需要，不以固定四个方向或多生成几张补足质量。

每个方向至少说明：

- 起点类别 starting_point（consumer-moment / product-benefit / counter-intuitive）与具体 starting_point_detail；
- 一句话人群矛盾；
- 一句话传播判断；
- 核心视觉对象；
- 对象之间的动作、因果、对比、转换或尺度关系；
- 产品或品类利益如何支持判断，品牌如何得到准确归属；
- 官方产品资产如何进入核心动作或关系；信息区品牌归属不能替代主关系中的产品参与；
- 单幅或系列规则；
- 最大误读、合规和制作风险；
- 低成本验证办法；
- 方法卡的本次输入、步骤、可观察输出与失败条件。

采用前方向句固定为“画面动作 + 产品关系 + 创意依据”。创意依据必须写清类型：人的时刻或洞察（consumer-moment）/ 产品真相或利益（product-benefit）/ 视角翻转或文化意味（perspective-reversal），三类都可以，不限定消费者时刻。清单每条含direction_id、statement、basis_type与非空basis；statement格式为“画面动作与产品关系；创意依据（中文类型）：依据原文。”，basis与句中依据逐字相同。只写画面结构而不交代依据无效，不能交盲评。检查者只收这一句（含依据及同文类型字段），不收其他作者理由或方向卡。中性格式示例：“速写者放下画笔，在放大的护腕包装上松开手指；创意依据（人的时刻或洞察）：长时间握笔后需要给手腕一个暂停时刻。”；“吸水材料接住鞋底，潮湿足印在落脚处变干；创意依据（产品真相或利益）：材料吸收水分，让湿脚印转为干爽落脚处。”；“茶罐盖朝上托起被搁置的棋子，罐身与棋盘同桌；创意依据（视角翻转或文化意味）：把被催促的输赢转换成饮茶时允许暂停的相处方式。”。示例仅解释输入格式，不保证创意放行。依据只是作者主张，检查者须判断它是否真的在画面动作与产品关系中成立；补一个好听但无关的依据不能构成转折。检查者在排序前逐条做绝对套路筛：产品顶替日常物件（桥、轴、座椅、积木、拼图块等）、产品拟人（长手脚/五官伴随）、接力/递送产品、产品放大成建筑或地标、产品+场景+微笑等，每条给出是/否及理由。套路但有新转折可例外：新转折可来自具体消费者/使用者时刻、产品利益或视角翻转，new_twist写清超出既有套路的额外关系，twist_basis登记consumer-moment / product-benefit / perspective-reversal。具体时刻与产品需求形成额外关系即可，不要求画面出现服用、使用或产品内部原理，也不要求产品作用过程可见。例如长时间握笔的速写者放下画笔，在放大的护腕包装上松开手指、休息片刻；吸水材料把潮湿足印变成干爽落脚处。只是对替身物件做空间、尺度或视角变换，且变换与消费者时刻和产品利益都无关，不算转折，例如电池变成滑轮吊起街区而仅有空间奇观。视角翻转须带来具体新关系；泛化休息或微笑、仅添加产品用途联系不自动算转折。示例仅解释判据，不复用反例库原句。再剔除关系近似方向，以具体转折、消费者时刻或产品利益的关联、意外感、创意本身及案例参照强度强制排序，不用绝对分；逐条判断接触、尺度和关系能否在一张图里成立，画不明白的不能进入出图。用途正确、联系清楚、包装放大或接线不单独证明创意贡献。普通日常、静态情绪和纪实摄影可按具体选择参与比较，不强制隐喻、奇观、症状或拟人动作。不得把“换成竞品还成立吗”或品牌独占作为本方向门的门槛或打分项。

按当前问题读取合格方法的实际步骤、诊断与失败边界，再形成关系及取舍；检索已返回这些字段，无须为了方法名重新搜整库。适用卡可直接重用；没有适用结果允许自行推导。把实际操作怎样产生或淘汰关系写在已有方向笔记中，方法不能只是事后标签。完整用法见本页方法段。

方向差异必须来自洞察、因果或视觉机制，不能只是换背景、风格、颜色、摄影质感或标题。同一创意仍可比较不同视觉风格；风格比较不冒充新的创意方向。按[视觉风格选择](../../workflow/visual-style-direction.md)在生图前明确图片面貌，不默认像真实照片。

### 方向门

独立盲评并入本阶段，先去重再排序、判可画，不能由作者自判替代。宿主路径：实际暴露的原生空上下文子代理（如 `fork_turns=none`）→ 新只读 `codex exec -s read-only --ephemeral` → 两者不可用就停止方向采用/出图并将同一检查包交用户/总控，不由作者代答。只发送固定 rubric、匿名编号的一句话清单、[真人反馈反例库](../../feedback/direction-counterexamples.json)和匿名案例机制参照；方法名、来源、作者理由、标题、方向卡、推荐、反例库以外的旧反馈和其他文件不进入检查者上下文。固定原文为 `scripts/validate_print_ad_run.py` 的 `INDEPENDENT_DIRECTION_RUBRIC_V6`；请求用既有校验器的 direction_request_v6，严格为原文 + `\n反馈机制反例库：\n` + 反例库UTF-8原文 + `\n案例机制参照：\n` + 参照UTF-8原文 + `\n方向一句话清单：\n` + 清单UTF-8原文（JSON数组，每项只有 direction_id、statement、basis_type、basis；后两项逐字对应句中依据）；三个输入都保存路径/hash；feedback-counterexamples必须与Skill随包反例库字节相同，不能漏条或偷偷改写。句中创意依据允许说明时刻、洞察、产品事实、利益或文化意味；不接收句子以外的作者理由、推荐或方法标签。

在盲评前沿用 query_case_library.py 检索活动包的资格合格学院奖平面案例（不扩库、不新建检索器）：

```powershell
& "<workspace-python>" scripts/query_case_library.py --kind case --competition academy-award --category print-ad --limit 100 --output "<运行目录>/02-direction/case-query.json"
```

保留完整原始结果；只选择获奖/入围且 reference_role 为 approved-method-reference 或 approved-limited-reference、适用本题赛道的3–5张卡作正向参照。卡中现有 allowed_use/allowed_uses 支持的一句话机制须去掉品牌、标题、年份、作者、链接和构图细节；只保留机制和获奖级别，不迁移原作表达。少于3张则如实保留全部；资格过滤后无可用案例，写 cases=[] 和非空 empty_reason，照常运行。检索分数只表示词法匹配，获奖级别本身也不证明本题创意成立。

每轮 case_references 绑定后台 $defs.direction_case_references（query_output路径/hash、cases逐条case_id/mechanism/award_level、empty_reason），不交检查者该文件。检查者只接收 reference-mechanisms 输入 {cases:[{mechanism,award_level}],empty_reason}，空时如实注明。查询须完成于输入准备之前。检查者先按反例库机制匹配，匹配项逐条引用entry_id和理由，判套路并在筛判及委托自动采用中直接拦截；任何新转折均不得改判合格，用户选择的override见下方合同。反例库未覆盖的机械空间/尺度花样同样按判据筛。检查者逐条记录是否达到参照强度，仅供排序；有参照时 reaches_reference为布尔，无参照时null并写原因。

方法卡的 anti_signals、failure_modes 和风险提示不能作为写成方向前的拒绝理由。“不改瓶型”“不添手脚”等不是自动禁令；适用卡至少先写成候选方向交独立盲评。拒绝只能绑定当前官方硬性约束或已观察到的具体失败，不能把风险预测写成已观察事实。method-retrieval.decisions沿用原字段并登记 candidate_direction_ids；rejected另填 rejection_basis（official-hard-constraint / observed-failure）和 rejection_evidence的路径/hash；硬约束可先排除，具体盲评失败或更弱排序可引用原始返回，说明失败项。无适用结果仍保留空结果，自行从不同利益角度推导。

- 视觉判断能够用一句话复述；
- 产品信息与主图共同回应传播任务，而非无关角标；
- 产品联系与本稿的具体创意贡献分别有可制作依据，品牌准确归属；
- 后台方向的对象关系明显不同，前台只展示入围比较所需内容；
- 风险和误读有可执行测试；
- 保留被剔除、未采用或失败的方向及独立理由；风险预测不得冒充方法卡拒绝证据。

### 方向清单交人选择与主画面来源

反例库对筛判和委托自动采用是硬拦截：同机制方向不得凭新转折、利益相关或重新解释判为合格；未委托时用户可在知悉原始判断后选择可画项，保留override。未命中库的新转折必须改变画面中的对象关系；检查者逐条写object_relation_change的objects、before、after和kind=object-relation。仅复述利益或依据，或加警告/暖光而对象关系未变，写null。

方向盲评完成后，把去重后的方向按原排序整理给用户，每条“一句话 + 依据 + 检查者一句评价”，同时如实标出排序、套路判断及理由、反例命中条目及理由、自动采用是否合格、可画性及理由。默认没有方向选择委托，用户可以选清单中任何可画项（含被拦项及非第一名）；须等待真实选择后锁定该原句并进入出图。被判套路或命中反例时保存user_override=true及对应判断引用，判断保持原样。all_weak=true时照样交清单，由用户选择可画项（override）或要求重新发散；不可画项仍不能出图。不得用模型推荐当用户选择。只有用户明确委托模型选方向时，才自动采用合格且可画的第一名，保留真实委托原话与来源，all_weak及重新发散规则保持原合同。

在现有02-direction保存direction-choice-list.json：presented_at、rows、user_facing_copy（路径/sha256）。rows每条含direction_id、statement、basis、rank、is_trope、trope_reason、counterexample_matches（entry_id及reason）、eligible（自动采用是否合格）、drawable、drawability_reason、checker_comment，按direction_choice_rows_v6从原输入和盲评复制；user_facing_copy为实际交给用户的简短清单。direction_adoption.choice_list绑定此记录。清单在盲评结束后展示，未委托时在用户选定之前展示；direction-selection使用$defs.direction_selection_record_v6，继续绑定真实用户原话和时间。用户选中任何is_trope=true或counterexample_matches非空的项时，须增加user_override=true与override_judgment={raw_return:对应末轮原始返回路径/sha256,trope_screen:该项完整原判}；校验器核对文件/hash、末轮身份、direction_id及逐字段原判一致。未标override、漏引用或引用不符均拒绝；合格非套路项可省略override或记false；委托不能记true。用户原话不得改写为委托或批准。清单前台可用direction_choice_judgment_text_v6生成每行判断摘要，须与后台原判一致。核心声明仍锁定用户所选方向statement原句，不能改成容易过关的句子。

主画面中的人物、场景、产品互动主体须来自实际生成/编辑或用户提供素材。不得在额度用尽或检查失败后用代码绘制SVG、矢量或几何拼贴整体重建主画面以凑完整稿；原生文字、排版、辅助图形、局部合成允许，但不得借局部合成之名重画全部主体。可编辑源是SVG不等于主画面可原生重画；隐藏或被遮住的生成切片不能充当最终主体来源。

## 6. 阶段3：低成本视觉原型

先用草图、原生形状、拼贴或低分辨率概念图测试关系。原型不追求最终质感，必须回答：

- 第一眼看到什么；
- 第二眼理解什么动作或因果；
- 产品在关系中做什么；
- 品牌通过什么被确认；
- 作品内文案与图像分别承担什么，合起来能否理解；
- 画面最可能被误读成什么；
- 系列中哪些不变量和变量可持续。

### 三类原型测试

1. **视觉先行测试**：暂遮文字以诊断图像承担的部分，再回完整图文判断；不把去字后独立成义设为所有广告的通过条件；
2. **产品先行测试**：只保留产品和主要关系，能否说明产品为何在场；
3. **缩略图测试**：在接近评审浏览尺寸下，主焦点、动作和品牌确认是否仍清楚。

按本次表达判断关系是否成立：动作型检查作用与结果；静态对比、形态、情绪和字图机制不强制拟人动作。作品内精炼文案可以承担必要语义，作者额外长说明不能替代成图。

### 内容形态与卡片例外检查

原型先用主体、动作、因果、比例、空间、材质、留白和阅读顺序建立画面，不从圆角信息盒、UI 面板、仪表盘或卡片网格开始。去掉容器边框后若只剩若干互不作用的文字块，说明卡片正在替代视觉关系，方向应回到原型重建。

只有作品真实表现界面、票券、商品卡等对象，或卡片确实表达离散同级、边界、归属或交互状态时，可按实际范围保留，包括整体界面；在已有方向笔记中说明语义与阅读依据，只有必要性不清时比较非卡片表达。整齐、科技感、易对齐或方便生成都不是成立理由。

## 7. 阶段4：分层生产

### 产品进入场景：官方参考编辑与标签回贴

产品作为场景内物体时，优先以官方产品图为参考，用图像编辑在足够大的局部蒙版内生成。蒙版包含产品所在的容器与接触结构（电池仓、握持手、桌面等），让透视、遮挡、接触、光影一起成立；不能只在原贴图位置的小蒙版内重画。生成参考、实际调用、蒙版和选择理由保存在已有生产/合成记录。

把官方资产的品牌/品类文字及标识区域按生成产品实际曲面与透视几何映射回贴，保留生成明暗。官方图层仅做几何变形和中性明暗融合，不改字形或颜色；被遮挡部分按真实遮挡裁切，底线是品牌字清晰可读。生成层在容器开口内完全覆盖旧图，核心不羽化带出旧像素，合成边界落在自然边缘；同时看完整轮廓与放大图，防止旧端帽、旧字或旧产品重影残留。

最终稿仅取允许蒙版内新像素。保留编辑前版本、二值允许蒙版和最终稿，以相同尺寸/模式逐像素零容差比对，登记差异范围与像素数，蒙版外必须为0；不能只对几个保留矩形抽查。产品独立展示时仍可贴官方原图，由作者按场景选择并记录理由；不得用贴图冒充场景内物体。

合成/回贴必须登记官方图层累计净旋转角及官方图内文字的实际阅读向量、水平/垂直翻转、透视矩阵，以及实际曲面映射参数文件。校验判定超过90°倒置或镜像即失败；例外只接受修正后当前局部放大与真实独立正向可读确认。倾斜/透视允许，不要求横平竖直，也不要求所有包装细字缩略可读。回贴后输出“官方原图 / 生成结果 / 最终”三联局部放大，逐项核对品牌、可见品类文字和标识，官方面没有的字不得补造。

具体记录字段、像素工具及独立第6问见[最终画面验收](../../workflow/final-pixel-review.md#产品合成与局部像素合同)。


制作输入应保留已选表达的核心对象、位置与关系，不只写材质、字样和职业道具。官方包装按场景采用官方参考编辑与标签回贴，或官方原件分层制作，但在完整原型中已有足够的产品与文字布局判断。产品利益可以决定构思，品牌在信息区完成归属；包装不必物理参与机关，接线/放大/挂物也不证明创意。独占主张仅在有实际依据时使用。


原型判断复用以下失败对照，不新增逐项人审：

| 看似完成 | 仍需检查的关系 | 修正方向 |
| --- | --- | --- |
| 产品准确嵌进设备，或放大成主角 | 是否只是位置正确的贴图；产品或品类特征如何决定动作与意义 | 改产品参与的因果关系，不能只放大或移动 |
| 给产品接手脚，操作了正确设备 | 用途是否只是被复述，消费者为什么应相信本次品牌判断 | 区分用途、消费者利益、事实依据；不要把拟人化自动记为创意 |
| 圆柱、纹样映射成滚筒与地毯 | 无说明画面里能否看到接触、受力和铺开的结果 | 理解失败先改动作，不能靠作者讲解维护机关 |
| 风格名改为模型或版画 | 首稿线条、色面、材质和空间是否真的改变 | 复核可见语言；连续失败重新判断机制，按用户放弃决定封闭方向 |

要求突出卖点时，每幅选择一个有依据的核心利益，让标题和画面动作共同承接；用途、消费者利益、产品性能事实分开推导，不能只贴参数。必要条件与主张一同保留：报警后开门次数不能省掉报警条件，打火次数不能改成使用年限，遥控范围不能虚构米数。此方法也适用于非性能判断，不强制所有命题数字化；本次品牌事实须取自当前命题，不照搬示例。

按公共内核执行官方资产、生成视觉和确定性对象的职责分离。

文字系统在方向与低成本原型阶段按[文字设计](../../workflow/typography-direction.md)确定：准确文案、传播语气、关键字形及图文关系进入已有方向笔记和首张代表稿；同时为本稿辅助句、场景词、产品信息和必要说明/出处安排真实空间，不把余文最后缩成页脚。不能用最终底图上的默认占位字完成文字方向审核。

局部字体修订同样先确定表达目标，再选实现；已有源格式不替代[文字设计](../../workflow/typography-direction.md)中的判断。

### 局部改稿的输入与输出

恢复时按[旧稿资料接入](../../workflow/delivery-and-recovery.md#旧稿资料接入当前范围)复用真实材料，补当前消费者需要的映射；充分已有资产使用现成provided-assets登记，不因本轮未生图省略生产就绪检查。

开始恢复旧稿时，先读取其实际图源尺寸、格式、色彩模式、DPI和可得源层，核对本轮输出用途。继承规格不足提前留明：局部审稿不默默扩大成全图重做，正式交付也不因旧稿获认可而豁免硬规格。复用现有技术检查，优先使用当前集合投影及准确文件选择；预期需要的格式转换在最终人审前完成。检查失败不通过降级run_scope或换profile消除。

首次接手旧稿同时整幅扫读，识别明显的继承文字缺陷；后续按修改及影响范围复查。检查范围不等于修改授权：已授权改善辅助文字时直接处理；明确锁定区域外的问题记录并报告，不扩大窗口，也不以未改认证通过。已有证据且未受影响的区域按[最终像素检查](../../workflow/final-pixel-review.md)复用，不每轮重验全稿。

### 生产顺序

1. 固化视觉判断、对象关系、视线、比例、产品作用、主要文字的字形与构图关系和Logo位置逻辑；
2. 依据图文关系选择制作路径：可独立的背景与标题分别制作，字图构成同一机制时共同绘制或生成并修整；不得生成伪Logo或伪包装。分层路线的背景可无字，但标题方向已确定；
3. 按所选风格检查造型、空间、纹理与边缘完成度，区分有意夸张和无意错误；摄影物理标准仅用于需要真实摄影感的部分；
4. 使用官方产品、包装与Logo保真合成；
5. 按既定方案制作或合成标题资产，以确定性排版加入功能信息和必要限定；核对实际文字、字组节奏与图文关系，不能在此临时套入上次默认标题；
6. 从原始输入或足够分辨率的制作文件完成高清稿；不能用放大概念预览图冒充高清细节，工具实际能力不足时按交付规范披露源层有效分辨率并调整生产方案；
7. 保存提示词、工具信息、初始生成、拒绝样本、选择和修改记录。

局部修订先继承已经认可的视觉机制、元素和语言，将本轮变化绑定到具体画面或原句；修改后同时核对累积要求。反馈“调整曲线表现”不能自动解释为删除曲线，“增补浪花”不能替换已经认可的路线。该原则不限于这些对象，具体项目按实际关系记录。

### 产品整合检查

- 产品的尺度、边缘、色彩及构图关系是否融入所选视觉语言；写实部分再检查光线、透视、接触阴影和景深，插画或拼贴不因缺少这些摄影特征自动失败；
- 产品尺寸和位置是否支持传播判断；
- 产品是否被裁切、遮挡或缩小到只剩角标；
- 包装文字、Logo和比例是否保持官方真实性；
- 产品在系列中的位置变化是否有叙事理由；
- 画面是否仍可被其他品牌产品无缝替换。

### 文字与信息层级

首次上字前，结合已选视觉试读拟写句段，检查词语实际指向、产品参与及图文分工，避免用文案外解释补联系。长度、留白与阅读层级服从当前要求；诗性和多义按实际图文判断，不强制把全部机制词写出或固定三行。已有定稿或局部修改授权直接复用，沿用当前内容检查点，不另加一次文字批准。

- 标题承担判断，不承担解释全部视觉；
- 品牌、产品、必要限定和参赛必备文字各有稳定层级；
- 小字只保留法定或必要信息；
- 功能中文、数字和标点使用可控排版；创意标题可采用已核字的字形资产，保留与其制作方式相符的编辑范围；
- 不用底板、描边、渐隐或阴影作为全局默认补丁；
- 不用重复圆角容器、悬浮面板或网页式卡片作为通用构图骨架；
- 每项可读性修复只应用于实际发生冲突的区域。

## 8. 系列系统

系列先声明：

- **不变量**：传播判断、核心机制、产品/Logo规则、字体系统、色彩家族和阅读顺序；
- **变量**：场景、人物、动作、对象、视角、证据或叙事步骤；
- **信息增量**：每幅为整体新增什么；
- **单幅成立条件**：脱离系列时仍能读懂核心关系和品牌。

新正式运行将方向判断保存为`series_plan`：`mode`、计划`units`、选择`reason`、`user_requested_series`，系列另含`shared_mechanism`；成员增量沿用下表，不另造平行记录。单幅须有当前命题、用户范围或无有效增量的具体理由；赛事上限不是单幅优先依据。代表稿通过后完成已授权成员；不同方向各自判断，不继承上一个方向的单幅豁免。最终清单与计划成员一致后才可交付，创意增量仍由实际画面及真实内容判断支持。

## 9. 人工视觉质量门

### 9.1 传播可理解性与可选受众实测

先看完整作品的实际表达，必要时遮字定位图像承担的部分；接触、受力与结果只用于相应动作型构思。展示时不以作者说明教人理解。最终用户认可记录为定性内容接受，不能推导为独立、计时或盲测。需要且实际开展受众测试时，可以让未参与创作的人观看后回答：

- 第一眼看到了什么；
- 发生了什么；
- 作品想让我相信什么；
- 记住了哪个品牌或产品；
- 哪个元素造成困惑。

测试记录观看条件、是否计时/盲测、原始问题与真实回答，不用引导性问题教受众理解。未开展测试时明确未做，不强制招募或制作所谓盲测板。完整图文仍无法理解时修复表达，不用作者长说明维护旧方案。新版证据使用 communication-clarity，记录方法为 author-inspection 或 user-acceptance；可选实测与当前版本绑定，格式见[最终画面验收](../../workflow/final-pixel-review.md)。

### 9.2 去品牌与换产品测试

- 去掉品牌后，视觉关系是否仍可理解；
- 恢复品牌后，品牌是否显著改变意义；
- 换成竞品或通用产品后，创意是否仍无损成立；
- 如果能替换，缺少的是产品机制、品牌资产还是具体场景。

去品牌或换竞品用于诊断联系，不要求每件广告证明绝对独占。恢复品牌后须有准确归属与有依据的产品利益；不编造专属意义，也不保留与品牌无关的漂亮图。

### 9.3 全尺寸与缩略图检查

- 缩略图：主焦点、动作、品牌和系列节奏；
- 全尺寸：文字、边缘、合成、包装、法定信息和生成瑕疵；
- 联系表：三幅共同机制、产品权重和信息递进；
- 单幅：脱离系列后的独立理解。

### 9.4 人工评审问题

1. 传播任务是否单一；
2. 完整图文关系是否明确，不依赖作者外加长说明；
3. 产品利益、品牌归属或实际参与是否支持表达；
4. 品牌归属与产品利益是否有依据；
5. 文案是否与视觉分工；
6. 系列是否有真实变量和信息增量；
7. 官方资产是否保真且融入空间；
8. 生成视觉是否有假字、假Logo、伪包装、物理或人体错误；
9. 构图、对比、视线和留白是否支持阅读顺序；
10. 可读性修复是否局部、必要且没有制造新噪音；
11. 是否存在伦理、隐私、羞辱、刻板印象或合规风险；
12. 作品在目标尺寸和评审场景下是否仍成立。
13. 画面结构是否由视觉关系而非无语义卡片、UI面板或仪表盘骨架支撑；若使用容器或整体真实界面，其内容语义是否成立。

凡画面含对白、人物口语或拟人发言，另做一次脱离策略术语的朗读检查：把角色、表情和场景说清后直接读出句子；若句子更像流程分类、命题解释、公益教育口径或为了对称而写的问答，就退回确定性文案层。策略词可以存在后台，但不能原样充当人物会说的话。标题负责收束判断，对白只承担当下动作或回应，二者不得重复解释画面。

## 10. 技术检查边界

人工视觉门通过后，按交付规范与赛事 profile 检查：

- 文件格式、尺寸、方向、分辨率、颜色模式和大小；
- 系列数量与文件命名；
- 图像可打开、通道和元数据；
- 交付后的AIGC记录/平台申报提醒、来源manifest和文件哈希；
- 只选择实际提交文件，不把联系表或预览图计入作品数量。

机器不能判断视觉关系、品牌不可替换、产品是否自然融入、构图是否高级、系列是否有意义、生成物理是否可信或实际观看是否理解。技术通过不产生人工内容通过。

## 12. 方法卡调用位置

| 阶段 | 可调用的问题 | 必须留下的本次产出 |
| --- | --- | --- |
| 命题 | 约束拆解、单一传播任务 | 任务句与硬约束表 |
| 研究 | 同质化、符号风险、场景动作 | 视觉领地和风险图 |
| 方向 | 同构、转译、联想、因果、尺度 | 有实质区别的关系及采用/淘汰理由 |
| 原型 | 传播理解、误读、品牌替换 | 低成本原型与测试记录 |
| 生产 | 图文设计、官方资产、按需分层与准确信息 | 实际制作路径和来源记录 |
| 系列 | 不变量、变量、信息增量 | 系列矩阵 |
| 评审 | 对抗式检查、局部修复 | 观察—影响—修改—验证记录 |

方向选择或创意/艺术返工时，定向读取适用卡的steps、diagnostic_signals、anti_signals与failure_modes。资格过滤继续适用；命中分数、卡名与来源不证明本题适用。复用方向笔记留下短链：当前问题 → 实际方法操作或自行推导步骤 → 产生/淘汰的关系 → 制作输入与可见变化 → 最可能失效的读法。先推导再制作，不事后补写；普通创作不强制逐卡验证登记。

方法操作应影响采用/拒绝或画面要求。关系清楚仍需判断具体表达价值；明确的方法作用、艺术语言落实与真人创意接受分别记录。method-validated须有相应完整证据，not-claimed不豁免推导质量。

反馈后的重用/重选及系列对照执行[反馈进入创作](../../workflow/feedback-to-creation.md)。在现有方向记录内保留本轮输入、关键步骤和可见变化；已查过资料不等于后续返工继续用了方法，不新增固定卡数或逐卡审批。

## 13. 最小运行证据链

运行清单用`run_scope`标明证据范围：`concept-only`只要求命题、方向、概念门、质量门结果和状态；`production-candidate`再要求官方资产、生产、人工视觉、技术；AIGC记录与平台申报仅交付后提醒；`delivery-candidate`另要求最终交付manifest。正确停在概念门不是残缺运行，但不得继承后续关卡的通过状态。

运行清单用`method_validation_status`区分普通创作与方法验证。`not-claimed`不强制完整逐卡验证登记，但不豁免创作及返工的实际推导质量；短链可保存在已有方向/原型记录。只有声明`method-validated`时，才必须登记`method_cards_used`、`method_cards_rejected`和`method_application`，且应用记录要能定位每张已用方法卡如何改变视觉关系、生产约束或取舍。方法卡ID本身不能充当验证证据。

一次完整交付范围的方法运行至少能定位到：

- 命题证据、传播任务和官方资产清单；
- 受控研究、同质化风险和参考采用/剔除理由；
- 实际探索的机制方向及选择理由；
- 方法卡本次输入、步骤、输出和失败条件；
- 低成本原型与三类原型测试；
- 生成提示、初始与拒绝样本；
- 官方资产合成、标题字形及功能信息排版来源；
- 系列不变量、变量和信息增量矩阵；
- 传播理解、去品牌/换产品、缩略图与全尺寸人工检查；
- 技术验证、交付后的AIGC记录/平台申报提醒、manifest、最终文件和运行状态。

简单任务可以合并记录文件，但不得省略视觉关系、品牌归属、系列递进和人工检查的实际证据。共享方法完整走通可记录 `method_validated`，现有运行可继续使用等价状态。作品完成以`delivery_complete`为准；报名、许可手续、AIGC/平台申报及上传不构成作品未完成。

## 最终像素证据

生产代表稿与最终交付必须执行[最终画面验收](../../workflow/final-pixel-review.md)，绑定实际目标渲染与当前文件哈希，覆盖全部适用页面并主动核验关键内容；仅在看不清或有实际疑点时补局部视图和对象测量，不要求逐对象建档。保留有内容依据的设计例外。技术规格通过不能替代视觉判断。

## 反复返工时的机制与系列复核

先看用户指出的失败发生在哪一层：产品没有参与因果、符号需要口头解释、正负意味读反、动作/接触不成立，或仅局部合成/排字问题。前几类回机制或对象动作重建；不能持续换材质、修蒙版或补说明再标待审。资产失败保留已认可机制；已授权整体修复不能擅自收窄成“一版底图”。已观察到核心误读或已选表达缺失时，先处理责任层，不以页脚、蒙版或字距改善冲销它；风险笔记与实际解决分开。关系已清楚但仍缺具体创意时继续推导表达价值，不只精修功能图示。技术精细、制作工整或内部高分不证明创意成立。

风格由本次品牌语气、传播任务和受众决定，防止跨命题惯性复用同一纸雕、肖像或写实发丝。角色属于原创设定时按命题匹配年龄、生活场景和目标人群；不能据肤色或无脸局部判断真实人物国籍。新颖漫画仍可能语气过激或把真产品降为角标；油光若读成漂亮发光，需要在画面里澄清负面后果，而不是增加解释。被拒但未生产的提案与实际失败图分开记录，不普遍禁用某种视觉语言。

延展前恢复 series_plan 中用户明确数量、各成员利益角色/动作增量和共同美术母版；预览、PDF/SVG副本及联系表不算独立成员。同一结只换手势/日程、同一对焦框只换红圈、组合利益稿重复单品功能，都须重新判断是否有新增意义。金/银/组合等成员角色需落实到产品与动作，不能只换标题。

共同母版约束实际线条、材质、光色、人物体系、产品尺度与字系；不只统一Logo和主题。延展后同时看单幅与并排系列，再看传播缩略。小字逐幅寻找空地会造成漂移；统一顶部也可能拥挤，不能把某次临时方案固定为通用规范。数量和风格一致性检查不能替代每幅增量判断。

局部反馈按已认可基线精确修改：新增一枚屑、仅右侧补乐谱、仅调指定色调，分别保留其余人物、动作、产品和文字关系。用实际前后差异核对影响；不要把历史某次89像素差异变成所有局部修改的阈值。反复修小瓶手部遮罩仍失败时，重建适当对象/握持动作与接触分区；具体瓶型服从本次允许资产与创意，不固定所有任务必须500mL。


## 独立核心检查与宿主路径

方向采用时，将被采用方向在独立盲评输入中的 statement 原句锁定为核心声明；不能到成图阶段另写更容易通过的句子。direction_adoption.claim_lock 引用真实保存的 JSON（direction_id、statement、statement_sha256、adopted_at、blind_review），绑定采用时间及方向盲评记录。statement_sha256 是原句原样 UTF-8 字节的 SHA256，不 trim、不改标点、不添换行。每稿 core_action、direction_id、core_claim_sha256 与对应锁一致；对照记录及原始返回都引用这个声明hash。失败稿同样保留引用，不能只锁末稿。

若原声明需改写，即更换方向：回方向阶段重新发散至少6个不同候选并覆盖三类起点、空上下文去重排序和可画判断，再按已有用户选择/委托采用并保存新锁。保留 previous_adoptions 的原采用记录、原锁和首轮盲评引用，新方向盲评 bundle.rounds 必须保留首轮并追加新一轮。采用后改声明也消耗同一重新发散额度；与“全部偏弱重发散”合计最多1次，不能靠改run名、新bundle或重置记录清空额度。首次已经用了两轮则不能再次自动更换方向。未改声明的完整主图返工可继续，新画面仍须兑现同一原句。

盲读用 INDEPENDENT_BLIND_RUBRIC_V2，单独列出 explanatory_devices（箭头、引导线/指向线、标注文字、透明重影/残影、图解符号、对话框等，无则[]），并写 relation_without_devices。对照逐字保留清单和去掉后的观察，填 device_removal.relation_still_holds 和像素理由。判据是：**去掉这些说明手段后，产品与核心动作的关系是否仍由造型、动作、接触、空间本身成立**。只有借这些手段才能读出关系时，第1、3问及第4问 creative_scene_not_generic 必须 false，按核心失败完整返工，不能靠添粗箭头、解释字或重影提高可读性而过门。

不是禁止一切线条、速度线或透明形态。速度线强化已经可见的移动，去掉后手仍握住产品、脚仍踩在瓶桥上，可以通过这项；仅用指向线说明产品补给人物、仅用透明残影讲前后位置，去掉后没有产品参与动作的接触/造型/空间证据，失败。需评估整个主关系，不能以局部“电池装在仓内”“道路像折纸”替代“产品驱动道路收拢/汽车回应”的创意联系。

与“不惩罚超现实与夸张”原则并存：巨瓶作桥、药盒作座位、道路折叠均可成为有意造型机制；不要求现实世界能发生。但超现实的产品关系要由画面演出，说明符号解释“它发生了”不能替代演出。装饰性重影去掉后主关系仍成立，不因出现重影自动失败。


每个完整稿一完成即在现有 `core_creative_review.completed_draft_render_records` 登记目标 render_record，包括首稿、失败稿、完整返工及局部修订后的新完整稿。逐稿保留独立 assessment，交付前 current_assessment_ids 必须绑定当前成图；不得只留下末稿或用作者自答通过。概念阶段没有成图可省略；已有完整稿仍须检查。

检查分两步，第一步完成并保存之前，检查者绝不能收到作者声明。盲读只给实际成图与固定 INDEPENDENT_BLIND_RUBRIC_V2，按像素说出动作/变化及方向、产品作用（看不出就写“看不出”）、可能两种读法的地方。不借标题和文案推断，不给方向卡、自检、设计说明、生产提示词、旧结论或失败诊断；使用中性文件名，不继承作者历史。官方产品图留到第二步，保证盲读素材输入清单及其hash只含成图。

盲读原始返回和记录保存后，再给同一成图、官方产品图、方向采用时锁定的一句核心动作/关系原声明（不改字、不夹带理由）及已保存的盲读记录，使用 INDEPENDENT_COMPARE_RUBRIC_V5 对照。可由同一检查者继续或另一次独立调用；盲读不可改写。动作、变化/因果方向、产品角色任一不一致，第3问必须为否；盲读看不出产品作用，第1问必须为否；主关系歧义（产品角色、动作方向、接触是否成立等）使第5问为否。次要歧义逐项保留，只记录不判失败。五问原合同如下，各答案引用盲读hash和对照证据键。

1. 产品是否进入核心动作/关系本身，而非旁边或前景贴图？
2. 不看文案能否认出核心动作？
3. 是否兑现声明关系：拿着看得出被拿住，坐着看得出坐在上面？**不要求写实，不惩罚超现实、夸张或刻意放大比例**，像素能读出有意机制即可；悬空、贴图、意外比例失调和接触不成立判否。不能用作者解释证明“有意”。
4. 去掉这个创意，是否仍是任何人都会画的普通场景（普通递水、拿产品微笑等）？**是则核心失败**；写实、精细或接触正确不能消除常规创意。记录时反向归一到 `creative_scene_not_generic`：普通场景为 false，具体创意成立为 true。
5. 陌生人三秒内能否说出产品与动作的关系？未做真实计时观众实验时，写独立检查者对快速理解的判断，不能虚构受众回答。

各项给基于像素的 observation，归一后任一 false 即回方向或主画面完整返工，沿用 full-rebuild 合同，失败不可删除、局部修改不可冲销；新图须新独立调用。检查者不替代原有最终人工内容认可。

按实际可行性优先：

- 宿主原生子代理/多代理。核对当前实际暴露的新独立会话能力，开启 multi_agent 不自动证明可调用。先以全新上下文（如 fork_turns=none）仅给成图和盲读固定规则，保存真实返回；保存后才给声明、官方图、盲读及对照规则。禁止全历史 fork 和额外文件读取，保存实际工具名、会话/调用标识或不可得原因。历史原生实验仅证明过单步路径可用，两步实跑须在当前环境核实。
- 无原生路径时尝试新只读临时 CLI：第一步 `codex exec --ignore-user-config --ignore-rules --skip-git-repo-check -s read-only --ephemeral -C <空检查工作目录> -i <artwork.png> --json -o <盲读原始返回.json> -`，stdin 仅盲读固定规则。完成并保存盲读后，第二次调用附同一成图和官方产品图，并只提交盲读记录与对照请求。请求严格按常量组装，见最终画面验收。仅使用当前宿主允许的选项、沙箱与审批设置；不继承作者会话、不生图。TMP/TEMP/TMPDIR、日志及必要运行时文件放许可区，禁止修改全局配置、绕沙箱或安装能力。CLI选项和真实登录/网络可用性须在当前环境核实，历史实验不构成永久承诺。
- 两条路径不可用或返回不完整：保持未通过，停止受影响稿件交付，给用户/总控同一最小检查包，附无法运行的具体证据；收到真实独立七问后再继续，作者不得自己代答。

固定规则用模块常量原样组装，不加本稿说明。沿用 independent_check 引用对照记录，其 schema 为 `$defs.independent_core_check_product_v2`，blind_read 引用 `$defs.blind_core_read_v2`；字段与时间/hash规则见[最终画面验收](../../workflow/final-pixel-review.md#平面核心创意逐项检查)。新运行 print-core-v4 / print-direction-v7 / print-product-v2 / print-ad.0.16.0；历史 print-core-v1/v2/v3/v4、print-direction-v1—v6、print-product-v1 和 0.1.0—0.15.0 保留原定义，不把旧认可转给新稿。

### 0.2.19 场景与迁移补充（print-ad.0.16.0）

新运行采用 `print-direction-v7`、`print-product-v2`、visual-review `2.3.0`。历史质量门、rubric 和 schema 定义保留用于只读复现。

出图前独立方向盲评按 `validate_print_ad_run.py` 的 `INDEPENDENT_DIRECTION_RUBRIC_V7` 与 `direction_request_v7` 构建固定请求。独立因果提示检查分两步：① 核心创意关系直接由什么产生？② 是否建立在产品自己做的事上？本职是用户买它要它做的事及正常直接结果。给其他对象提供能量、原料或功能的赋能型产品，其赋能对象因此做到的事也算本职结果。由本职/正常结果/赋能结果产生的核心效果合格；来自产品未参与的另一系统或环境、产品只是前提或触发者的效果不合格。不以同类或其它手段也能完成本职拒绝，不虚构产品能力。理由写明本职、赋能对象及提供的东西、核心直接来源与结果归属。多品类示例仅用于说明：设备靠电池供电发光投影、玩具车行驶、点火后的烹饪蒸汽合格（电池不加热汤）；遥控借车辆自身车灯、开门借独立走廊灯投影不合格；药品/健康品缓解症状后的恢复状态、饮料/食品补水或口感/成分带来的变化合格，只作场景道具且效果来自别处不合格，均须产品说明支持。逐条填写core_creative_relation_direct_source、core_relation_still_holds_without_product布尔、reason；旧布尔字段名为负向提示标记，第②步是→false合格，否→true不合格。不设按品类的规则分支。因果一问是提示项，用于提醒“创意是否借用了产品没参与的效果”，不作为门槛。逐条保留直接来源、结论与理由，方向选择清单原样展示且在用户选择前可见；rows保留去重后可选排名，causal_advisories覆盖本轮全部输入（含去重项），不改变可选排名；缺字段、覆盖不全或清单遗漏提示仍须拒绝。因果结论不参与合格排序、可画前列、all_weak、自动采用（含委托）、user_override需求、版本迁移承接或生产守卫决策；因果不合格无需用户覆盖。排序与all_weak只按既有套路/可画性规则判断，不能按因果结论压排序或变更采用。新增causal_check覆盖全部输入，包括去重项；检查者不代替用户选择，其余v6返回字段保持。 套路/不可画仍按现有user_override记录；其引用的causal_check仅绑定原返回，不是覆盖要求。

仅Skill版本迁移重评可新增 kind=user-choice-carryover 的选择记录。decided_at保留原实际用户时间，carryover.carried_at为新记录时间；绑定原选择路径与哈希、原句文件、真人来源事件及来源哈希、新旧version.json、新盲评与三种新判断，说明reason及re_review_reason=skill-version-migration。原句以UTF-8字节逐字比对，不修剪、改字或补依据。原话与时间须可追溯；新套路或不可画判断只有原用户已有覆盖且绑定对应旧原始判断时可承接，否则回用户确认；因果判断只承接原提示，不影响是否可承接，也不要求覆盖。旧授权、旧守卫拒绝、旧返回一律不改。承接不等于新增用户认可，也不覆盖其它生产门。

生产记录逐产品登记product_scene_plans（schema见visual-review的product_scene_plan_v2）：official参考图、registered_at、role、container_contact_structure、覆盖容器/接触的edit_mask和container_contact_mask、canvas_size、generation_method及choice_reason。派发请求声明product_contract=print-product-v2、product_operation、product_targets、prepared_at及product_plan_record路径哈希，并将官方图和蒙版列为input_files。缺计划拒绝生成/编辑及本地合成；官方贴图只能role=display-object并写display_reason。产品局部返工也先登记新计划。

每个完整稿的独立对照采用print-core-product-v2，增加第7问product_in_scene，并逐产品绑定product_triptychs；独立检查输入含实际三联图，原始comparison.product_scene逐产品回答透视、遮挡、接触与光影是否统一而非贴片。任一失败是核心失败；作者自评、标签检查或其它通过不得抵消。产品问题可走product-local-repair回production，保留计划、失败、区外零变化证据，取得新版本新独立七问；原五问失败仍完整返工。缺独立原始返回不能交付。

## 次级文案：可用，也可不用（print-ad.0.16.0）

按[次级文案原则与文字角色范围](../../workflow/typography-direction.md#次级文案可用也可不用print-ad0160)决定是否使用，并在现有作品记录中登记一句理由；未使用不算缺项。新成图使用 `print-secondary-copy-v2` 与visual-review `2.5.0`；全部旧合同与文案/排版检查保留。

每稿用 `text_elements` 登记标题、次级文案、页脚事实限定或必需信息、品牌/产品标识、场景文字。只有角色为 `secondary-copy` 的元素进入本原则的内容、字号/字重、420px可读、系列及独立语义检查。独立输入用实际文字/位置及scope hash明确范围；其他文字区的意见只留作信息，不触发次级文案返工。页脚限定是否解释画面不由本原则判断，页脚小字不套420px下限，既有页脚检查原样执行。

使用时只补画面与标题未给出的官方事实或命题信息，语气克制、不复述或解释画面，层级低于标题并合成一个阅读区。脚本和独立检查失败只返工文字层，保留旧返回，局部修改后绑定新图及文字蒙版、区外零变化并取得新独立检查；核心/产品失败继续独立处理。“产品名｜卖点”只是一种例子，不是默认或必需格式。
