# 生图工具与宿主适配

在选定[视觉风格](visual-style-direction.md)后，只读取本次工具分支。通用要求是主体、关系、视觉语言、关键特征与必须保持的内容；实际下发时转换为当前入口接受的提示词、参考输入和设置。以下不是提供方白名单，也不是已在所有平台实测的承诺。

## 先识别实际执行路径

本 Skill 不将 Canva 生图纳入工具选择、适配或推荐范围。

区分宿主（助手环境）、生成模型及版本、入口（内置工具/API/网页/本地工作流）。模型支持某功能不代表入口开放它。沿用用户选择和既有授权；否则依据任务需要、可用性及成本选择，不默认某厂商优先。查看当前工具说明，必要时查官方文档；未知参数不猜测，不因缺少品牌名就判定工具不可用。

仅核对任务需要的生成/编辑、参考输入、局部修改、输出尺寸与文件取得方式等能力。记录利用已有前检 evidence 和提示词即可，不新增每次必填的适配表。明确不可用时给替代制作路径，不把已批准风格迁就为工具的默认效果。

## 工具分支

以下官方指导于 2026-09-26 核对。模型、接口和界面持续更新，版本相关参数以当次入口为准。每个例子都是提示词编写示范，未承诺一次生成成功。

### GPT Image

以清晰自然语言描述任务，复杂要求可短分项。说明参考图序号及职责；编辑时写明改变和保留的内容。将“高质量”和具体风格分开，非摄影任务不套用摄影示例的镜头细节。工具支持的尺寸等作为设置传入，不能把 API 字段或其他工具语法假装成本入口参数。[官方指导](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)

同题示例：用于校园运动海报。用二维运动漫画画一名学生沿弧形轨迹向前跑，操场在背景展开。粗细变化墨线、蓝白平涂和局部网点构成画面，速度线随跑动方向集中。保留顶部标题空间。

若提供产品与风格两张参考：明确第一张只用于产品身份，第二张用于线条和色块；不能把第一张的摄影背景带入。包装身份与正文文字必要时用原生合成完成。

### Gemini 图像生成

确认所用的是具备图像输出能力的具体模型，而非仅能理解图片的模型。用连贯描述表达场景关系、用途与视觉特征；复杂编辑拆成有针对性的修改，并在下一轮重述重要保留项。图像与文字如何提交、历史上下文如何传递及输出选项依入口说明执行。[官方指导](https://ai.google.dev/gemini-api/docs/image-generation)

同题可沿用上面的语义要求。定向修改示例：沿用刚才画面的跑动轨迹、人物位置和蓝白配色，只将人物与背景改成明显的二维墨线轮廓、平涂色块和网点阴影，保持标题空间。若当前入口没有上一轮图像上下文，重新附上目标图，不能假设它记得。

### Imagen

围绕主体、背景和具体风格写明确描述，按入口提供的设置配置画幅。与 Gemini 图像生成分开判断，不预设多轮编辑、参考图或负面提示在所有 Imagen 版本都可用。[官方指导](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/image/img-gen-prompt-guide?hl=zh-cn)

同题示例：一名学生沿弧形轨迹奔跑的二维运动漫画插画，背景为展开的校园操场，粗细墨线、蓝白平涂色块、局部网点阴影和集中的速度线，顶部有整洁标题空间。画幅设置与提示分开；不是把绘画描述换成“广告照片”。

### Midjourney

优先用简洁且相容的视觉描述，避免把执行说明和多轮修改合同塞进画面内容。需要风格参考时使用当次版本/入口的 Style Reference；参考的作用是视觉语言，文字不要与其冲突。`--sref`、`--ar` 等仅在支持的入口按文档使用，不输出到其他工具的自然语言提示中。[提示词基础](https://docs.midjourney.com/hc/en-us/articles/32023408776205-Prompt-Basics)、[风格参考](https://docs.midjourney.com/hc/en-us/articles/32180011136653-Style-Reference)

同题示例：二维校园运动漫画，学生沿弧线向前跑，背景操场展开，粗细墨线，蓝白平涂，网点阴影，集中速度线，顶部标题空间。

与 GPT Image 示例保持相同意图，但把程序式说明压缩为画面描述。若用网页，将所需画幅和风格参考放入对应控件；只有确认命令入口支持后才追加参数。命题要求精确包装时，不能把风格参考当成产品身份保真保证。

### Adobe Firefly

先确认当前选中的模型。文字写主体、动作和风格特征；使用入口开放的风格参考与构图参考控件时，分别承担视觉语言与布局，避免把界面选项写成虚构的文本语法。选择第三方模型后，重新核对该模型及当前入口功能。[提示词指导](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/writing-effective-text-prompts.html)、[风格参考](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/reference-images-for-styling.html)、[第三方模型入口示例](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/generate-images-using-flux.html)

同题可使用简洁漫画描述；若上传参考，用风格控件传达墨线、平涂和网点，构图控件传达跑动轨迹。以当前界面实际可见选项为准，不擅设不存在的参考强度或假装已经点击。

### FLUX 与 Stable Diffusion / 本地工作流

不能仅凭“扩散模型”统一提示词语法。FLUX.2 [pro]/[max] 指导强调主体、动作、风格、环境；其官方指导不支持负面提示，应正向描述所需结果。这不能推广成全部 FLUX 版本的参数合同。[FLUX.2 指导](https://docs.bfl.ai/guides/prompting_guide_flux2)

同题 FLUX.2 描述可从“学生沿弧线奔跑，二维运动漫画，粗细墨线、蓝白色块、网点阴影，展开的操场背景及顶部标题空间”开始；不要另发一串负面词来代替风格描述。

Stability 的部分图像生成接口提供 `negative_prompt` 等控制，但须核对具体端点。使用本地 Stable Diffusion、FLUX 或其他工作流时，先看模型与节点实际接受的输入，再决定提示词、负面提示、参考条件或控制方法；不默认 LoRA、ControlNet、括号权重或某组采样数值可用。[Stability API 参考](https://platform.stability.ai/docs/api-reference)

支持负面提示的入口可针对真实偏离使用少量排除项，如非摄影目标出现皮肤摄影纹理；仍须在正向提示明确墨线、色块和空间。不复制巨长通用负面词表，不为使用本 Skill 自动安装模型或下载权重。

### 未列出的工具

读取当前工具说明，以相同视觉要求生成最小可执行提示；只加入有依据的设置。若身份不明但接口明确，可以按能力继续；若任务所需能力不明，先解决该项缺口。没有必要为使用一个新工具扩充整个风格分类。

## 外部执行与跨宿主恢复

没有直接生图工具时，按[生产路径前检](visual-generation-capability-gate.md)区分外部生成、已有充分资产和确实无生产路径。用户已选择外部工具则直接准备可复制的提示词、可用设置、带角色说明的相关参考素材和所需输出；不再要求确认同一选择。只在真实缺少路径时合并提出最小问题。

外部生成期间继续不依赖图像的工作。回来时取得实际图像文件，查看目标风格、内容、品牌和生产适用性，再保存相对运行目录路径与完整性信息。仅有提示词、链接或“已生成”的文字不能当成已拿到视觉资产。小范围回传检查可引用已有视觉审核记录，不另设人审关卡。

发现当前宿主的 Python/其他依赖、文件读取、图像查看和交付能力；Codex 的 load_workspace_dependencies 等只是可用时的途径。包内 `scripts/` 命令相对于 Skill 根目录执行，运行材料使用明确的运行目录；使用当前 shell 对应的调用方式，不将 PowerShell 的 `&` 复制到其他 shell。无本地执行能力时提供可移交命令及材料，不声称已经运行；无图像查看能力时需要能查看图像的路径完成相应验收。

换宿主时移交现有运行清单、相对路径资产、提示词/参考分工及既有决定，重新确认可用工具后继续。宿主专用元数据不承担唯一指令，用户无需具有 Codex 专用插件才能理解和使用本流程。

## Python 与命令执行约定

包内示例的 `<workspace-python>` 是占位符：替换成当前宿主已经发现、且能运行所需脚本的 Python 可执行文件路径，不要原样输入，也不代表必须调用 Codex 工具。可先用宿主依赖发现功能，或在 PowerShell 用 `Get-Command python, python3 -ErrorAction SilentlyContinue`、在 POSIX shell 用 `command -v python3` 找到候选解释器，再用下列命令确认实际路径。

先进入 Skill 根目录；把路径占位符替换为真实值。含空格的路径保留引号。参数中的 `<...>` 表示待替换值，`[--选项 ...]` 表示可选项，实际执行时不保留尖括号或方括号。

PowerShell：

```powershell
Set-Location "<Skill根目录>"
& "<workspace-python>" -c "import sys; print(sys.executable)"
& "<workspace-python>" scripts/validate_run.py --run-dir "<运行目录>" --manifest "<运行清单.json>" --handoff "<交接目录/handoff.json>" --output "<新回执.json>"
```

POSIX shell（bash/zsh 等）：

```sh
cd "<Skill根目录>"
"<workspace-python>" -c "import sys; print(sys.executable)"
"<workspace-python>" scripts/validate_run.py --run-dir "<运行目录>" --manifest "<运行清单.json>" --handoff "<交接目录/handoff.json>" --output "<新回执.json>"
```

其余赛道命令沿用同一参数，按当前 shell 调整可执行文件调用方式。统一入口的 manifest、handoff、output 相对 `--run-dir`；独立技术检查脚本的路径参数按该脚本 `--help` 解释，避免与运行目录重复拼接。

需要位图读取/验证时，使用同一个解释器执行 `-c "from PIL import Image; print(Image.__version__)"` 确认 Pillow。缺依赖先选用已有合适环境；需要安装时，在宿主允许的项目环境中按其依赖管理方式安装 Pillow，再用该解释器复测。不要自动修改用户全局环境。依赖错误说明本次检查未完成，不代表图像损坏，也不要求重新生成图像。无执行能力时交接待执行命令，不登记为通过。

## 判断结果

核对实际画面，不靠提示词命中风格名判定。工具更换后检查意图是否保持，不要求不同模型生成相同像素；误差按范围定向修正，不无限重抽。实际运行记录以真实模型/版本（可识别时）、入口及结果为准，区分已实际生成验证、仅文档核对和待核验。

画面中的半透明纸材、透叠色层与文件背景透明是两件事，按用途分别说明；要求不透明纸底时仍核对实际文件的透明通道和空洞，不能只看调用参数就认为满足。生成任务成功或返回缩略图只能支持相应程度的观察；原始尺寸元数据不等于已取得原图。需要检查细节或交付时取得足够清晰的实际资产，暂时只有预览则保留这一限制，不用放大缩略图宣称细节通过。

## 恢复环境、导出及来源回退

在运行内保存实际验证的解释器、项目依赖目录和必要导入结果；冷恢复先核对它们仍有效，无效再发现环境，不重复全局安装。通用Skill不内置某台机器的绝对路径；依赖入口是运行证据，不是跨宿主固定配置。

栅格导出先核对预期像素与小样实际尺寸，再导出最终文件；毫米视口与density在部分渲染器可能重复缩放，不把DPI元数据当成已验证像素尺寸。统一入口manifest、handoff、index、output都相对run-dir并留在其内；output必须新建，不覆盖旧回执。prepare_visual_views的zoom允许1.5—4，原倍率裁切不自动等同于已放大的细节视图。

官方材料访问失败时检查现有可用的只读入口并回退，单个入口失败不等于材料不存在；没有成功取得内容时保持待核验。文件名日期、正文版本日期和核对日期分开记录，出现差异按实际文件哈希、正文及官方身份判断，不靠文件名日期推断版本，也不把不影响事实的差异自动升级为生产阻塞。
