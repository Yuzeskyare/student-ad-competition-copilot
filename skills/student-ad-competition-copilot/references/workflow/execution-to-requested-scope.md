# 持续执行到请求范围协议

本协议把用户已经授权的创作目标转换为可恢复的执行边界。它不扩大用户目标，也不绕过人工内容门、事实边界、权利要求或外部操作授权。

## 执行合同

开始或恢复运行时，从用户原话、现有产物和最近阶段回执确定并保存：

- `target_scope`：本轮要达到的运行范围、产物或修复目标；
- `stop_condition`：什么可验证状态表示本轮完成；
- `current_stage`：当前实际落点；
- `next_action`：依赖已满足的唯一动作；
- `pause_reasons`：仍可能要求人工决定或外部材料的已知边界。

用户明确指定范围时按原话执行。例如“完成P2后汇报”“做到五页样稿”“生成可交付终稿”都给出不同停止条件。用户说“推进下一步”时，范围是上一张有效回执中的唯一下一动作及其必要验证；没有有效回执时，先从保存状态计算该动作。不能把“下一步”解释为自动完成所有后续生产或投稿。

## 连续推进

在`target_scope`尚未完成时，按以下循环执行：

1. 完成当前`next_action`及其必要产物；
2. 运行该动作要求的事实、内容或技术检查并保存结果；
3. 根据新状态生成阶段回执；
4. 若没有暂停条件且停止条件未满足，立即计算并执行新的唯一下一动作；
5. 停止条件满足后，验证目标范围完整性，生成完成回执并停止。

阶段通过、计划写完、dry run成功、脚本生成、单个校验通过或普通进度回执都不构成默认暂停理由。不得只说明“接下来可以……”而把已授权且依赖满足的动作留给用户再次批准。

## 合法暂停条件

只有以下情况暂停：

1. 低负担人工审核协议要求真实人类选择或确认；
2. 缺失信息会改变赛道、命题身份、核心事实或主张、交付范围，或者不可逆高成本生产；
3. 官方规则、保真资产、权利或许可对受影响动作形成`hard-stop`；
4. 实际报名、上传、发布、付费、对外发送或其他外部不可逆动作没有明确授权；
5. 工具或环境失败经过安全重试、替代路径或回滚后仍阻止执行。

暂停只阻止受影响的动作。先完成其他不依赖答案且属于目标范围的工作，再保存状态并提出一个最小问题或唯一解除动作。偏好不明确但可用可撤销假设继续时，遵循最小信息协议，不暂停。

## 失败、反馈与恢复

观察到质量失败后，若修复不改变用户已选方向，自动回到最近责任阶段，保留失败版本，完成修复、复测并继续。若修复会改变核心创意方向、最终内容判断或用户明确偏好，进入一个低负担人工检查点。

工具失败先保留幂等状态，使用安全的重试、替代执行方式或已有回滚机制。成功恢复后继续原目标；不能因为一次可恢复失败把目标缩小。恢复会话时从保存状态重新计算，不重复已完成动作。

用户的中途消息默认是对当前目标的纠正、补充或进度询问。回答后更新受影响的`target_scope`、`stop_condition`或输入并继续；只有用户明确取消、替换为不兼容目标或要求停下时才终止原执行合同。

## 完成边界

只有目标范围要求的产物存在、适用质量门已通过或有明确边界通过、状态与证据一致时，`stop_condition`才成立。完成后不自动升级到更远范围：概念完成不自动进入高清生产，生产候选完成不自动投稿，交付文件完成也不自动上传。

完成回执必须写明已完成的准确范围、验证结果、仍不属于本轮的边界，以及“唯一下一动作：无，当前请求范围已完成”。
