# 低负担人工审核协议

质量门中的`human`检查先由模型准备证据，不把内部检查表逐项转交给用户。模型先完成事实核对、机器自检、自我反驳、明显错误修正和候选收束，再把同一阶段、同一批产物的检查合并为一次低负担审核。

## 检查点载荷

一个检查点包含：

- `review_scope`：本次判断覆盖的版本、页码、候选或系列范围；
- `review_artifact`：用户能直接看到或读到的联系表、候选文本、样稿、渲染或对照材料；
- `decision_reason`：为什么此刻必须由人判断，以及该决定会影响的后续工作；
- `assistant_recommendation`：推荐选项及可观察依据，同时保留真正不同的备选；
- `minimum_reply`：允许用户只回复“通过”“选B”或一个具体问题；
- `decision_mapping`：模型将自然语言反馈写入哪些检查项、状态、影响范围和返回阶段。

## 何时暂停

只在以下节点等待真实人工决定：

1. 多个可行方向会形成不同作品且无法由既有偏好确定时，选择方向；
2. 平面低成本原型、文案入围稿或策划五页样稿准备扩展为高清、终稿或全稿前，确认代表性内容；
3. 当前运行范围准备登记`content_pass`前，确认最终内容版本和覆盖范围。

如果用户已对同一版本、同一范围作出清楚判断，直接写入评审记录，不以改写后的同义问题重复审核。纯客观问题、事实缺口、技术规格、路径字段和模型能无损修正的明显错误，由模型处理并报告，不消耗人工选择。用户委托模型选择时可以继续可逆步骤，但委托本身不等于人工内容通过；缺少真实人工确认时保持`content_pass: pending`。

## 负担与覆盖边界

概念选择默认最多展示3个真正不同的方向；同屏比较默认最多5项。超过时先由模型按命题适配、差异性和明确失败证据收束，或拆成有覆盖记录的小批次。平面系列用联系表加必要的全尺寸细看；文案只展示入围稿及必要的朗读差异；策划先审五页样稿，再审全稿联系表和需要放大的关键页。用户不填写质量门表格，模型把反馈转成“观察 → 影响 → 修改 → 验证”记录。

代表性样本通过只允许进入已声明的下一阶段，不能自动令未展示的系列成员、文案候选、策划页面或最终版本获得`content_pass`。最终人工决定只覆盖评审者实际看过的版本和`review_scope`；后续实质修改会使受影响检查重新进入`pending`，无关检查保持原状态。
